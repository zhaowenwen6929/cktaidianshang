# 图片处理能力业务流程补充

## 1. 文档目的

本文件用于补充图片处理类能力的内部业务流程约束，重点服务于以下场景：

- 需求导出
- 产品评审
- 后端能力拆分
- 接口扩展预留

说明：本文件描述的是内部处理流程，不要求在前端界面中直接体现。

## 2. 一键抠图业务流程补充

### 2.1 流程目标

一键抠图需要面向电商多品类场景持续优化，不能将后端能力固定为单一抠图模型。系统需要具备按品类路由不同抠图能力的可扩展机制，以便后续持续补充特殊商品类目的抠图效果。

### 2.2 主流程

1. 用户上传商品图并提交一键抠图任务。
2. 系统先对上传图片进行品类识别。
3. 系统根据识别出的品类，匹配对应的抠图能力或策略。
4. 后端调用对应品类的抠图处理链路执行抠图。
5. 处理完成后，将抠图结果返回给用户。

### 2.3 能力设计要求

- 前端层面只保留“一键抠图”统一入口，不暴露品类路由细节。
- 后端能力层面需要支持“按品类分发”的策略扩展，而不是写死单一模型。
- 品类识别与抠图能力映射关系应可配置，便于后续新增特殊品类。
- 当新增某一特殊品类抠图能力时，原则上不应要求前端改版，只调整后端识别与路由策略。
- 需求导出时，需要明确标注“一键抠图具备按品类扩展专用能力”的设计前提。

### 2.4 预留扩展方向

- 通用品类使用基础抠图能力。
- 特殊品类可挂接专用抠图能力。
- 后续可继续扩展：
  - 透明材质类商品
  - 毛绒/发丝类商品
  - 饰品/镂空类商品
  - 反光材质类商品
  - 复杂边缘结构商品

### 2.5 导出需求时建议保留的描述

建议在正式需求文档、后端接口文档或流程图中保留以下描述：

> 为保证电商场景的抠图效果，后端持续完善补充特殊品类的抠图能力。用户上传图片提交后，系统先识别图片品类，再根据品类调用不同的抠图能力，处理完成后将结果返回给用户。
