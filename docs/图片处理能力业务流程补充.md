# 图片处理能力业务流程补充

## 1. 文档目的

本文件用于补充图片处理类能力的内部业务流程约束，重点服务于以下场景：

- 需求导出
- 产品评审
- 后端能力拆分
- 接口扩展预留

说明：本文件描述的是内部处理流程，不要求在前端界面中直接体现。

## 2. 一键抠图业务流程补充

### 2.1 流程目标

一键抠图需要面向电商多品类场景持续优化，不能将后端能力固定为单一抠图模型。系统需要具备按品类路由不同抠图能力的可扩展机制，以便后续持续补充特殊商品类目的抠图效果。

### 2.2 主流程

1. 用户上传商品图并提交一键抠图任务。
2. 系统先对上传图片进行品类识别。
3. 系统根据识别出的品类，匹配对应的抠图能力或策略。
4. 后端调用对应品类的抠图处理链路执行抠图。
5. 处理完成后，将抠图结果返回给用户。

### 2.3 能力设计要求

- 前端层面只保留“一键抠图”统一入口，不暴露品类路由细节。
- 后端能力层面需要支持“按品类分发”的策略扩展，而不是写死单一模型。
- 品类识别与抠图能力映射关系应可配置，便于后续新增特殊品类。
- 当新增某一特殊品类抠图能力时，原则上不应要求前端改版，只调整后端识别与路由策略。
- 需求导出时，需要明确标注“一键抠图具备按品类扩展专用能力”的设计前提。

### 2.4 预留扩展方向

- 通用品类使用基础抠图能力。
- 特殊品类可挂接专用抠图能力。
- 后续可继续扩展：
  - 透明材质类商品
  - 毛绒/发丝类商品
  - 饰品/镂空类商品
  - 反光材质类商品
  - 复杂边缘结构商品

### 2.5 导出需求时建议保留的描述

建议在正式需求文档、后端接口文档或流程图中保留以下描述：

> 为保证电商场景的抠图效果，后端持续完善补充特殊品类的抠图能力。用户上传图片提交后，系统先识别图片品类，再根据品类调用不同的抠图能力，处理完成后将结果返回给用户。

## 3. 提取线稿提示词补充

### 3.1 功能范围

对应前端工具：

- `image-lineart`：提取线稿

当前前端可配置字段：

- `lineartStyle` 线条类型

当前选项：

- `清稿`
- `草图/速写`
- `精细素描`

说明：

- 当前“提取线稿”只有 1 个业务操作维度，即 `lineartStyle`。
- 后端建议按“通用基础提示词 + 类型提示词 + 通用质量约束 + 通用负面约束”的方式拼装最终 prompt。
- 若后续新增“保留背景/去背景”“线条粗细”“黑白/单色”“是否保留阴影”等选项，可继续沿用本节结构扩展。

### 3.2 提示词组装建议

建议统一按以下顺序拼装：

1. 任务目标
2. 主体保留要求
3. 线稿类型提示词
4. 通用质量约束
5. 通用负面约束
6. 用户补充说明（如后续接入）

建议后端输出结构：

```ts
type ImageLineartPromptBuildResult = {
  finalPrompt: string;
  segments: {
    task: string;
    subject: string;
    style: string;
    quality: string;
    negative: string;
    supplement?: string;
  };
};
```

### 3.3 通用基础提示词

#### 3.3.1 任务目标段

```text
任务目标：将上传图片中的主体转化为干净、可识别、可直接用于设计、排版、印刷参考或二次创作的线稿图。输出重点是“结构清晰、轮廓准确、线条可读”，不是生成新的主体内容。
```

#### 3.3.2 主体保留段

```text
主体要求：准确保留原图主体的外轮廓、主要结构、关键比例关系和典型识别特征；优先提取主体线条信息，弱化或去除无关背景干扰；不要随意改动主体造型、零部件数量、开孔位置、连接关系、装饰位置和核心结构。
```

### 3.4 线条类型对应提示词

#### 3.4.1 `lineartStyle = 清稿`

适用理解：

- 偏“干净描边”
- 适合抠结构、出干净线稿、做后续上色或设计加工

建议类型提示词：

```text
线稿风格：输出干净利落的清稿线条效果，以清晰外轮廓和必要结构线为主。线条规整、边界明确、疏密控制稳定，尽量减少多余笔触、排线和涂抹感。整体更接近整理完成的标准线稿，背景尽量纯净，主体识别优先，适合后续继续编辑、上色、排版或印刷使用。
```

#### 3.4.2 `lineartStyle = 草图/速写`

适用理解：

- 偏“概括表达”
- 允许一定手绘感，但仍要保证主体可识别

建议类型提示词：

```text
线稿风格：输出具有草图/速写特征的线条效果，保留适度手绘感、概括感和快速勾勒感。线条可以有轻微虚实变化与自然笔触，但必须保持主体外轮廓准确、主要结构完整、整体识别清楚。画面应体现草图表达的轻松感，不要变成凌乱涂鸦，也不要丢失关键结构信息。
```

#### 3.4.3 `lineartStyle = 精细素描`

适用理解：

- 偏“结构更充分”
- 允许更丰富的细节线与适度明暗表现

建议类型提示词：

```text
线稿风格：输出精细素描风格的线稿效果，在保证主体结构准确的前提下，补充更丰富的轮廓线、转折线、纹理线和必要的明暗排线。细节刻画要服务于体积感、材质感和结构说明，整体细腻但不脏乱，层次丰富但不糊成灰面，适合需要更强表现力和细节说明的线稿场景。
```

### 3.5 通用质量约束

以下内容建议所有 `lineartStyle` 共用：

```text
质量要求：线条需清晰、连续、自然，主体结构准确，比例关系稳定，边缘完整，不缺线、不粘连、不漂移。输出应尽量去除背景杂讯、压缩脏边、污点、乱码纹理和无意义碎线，保证主体层级明确、轮廓闭合关系合理、关键细节可辨认。若原图存在复杂纹理、反光、褶皱或遮挡，应优先保证主体主结构正确，再适度保留有助于识别的细节。整体画面保持高可读性、高完成度、适合继续设计加工使用。
```

可选追加质量短句：

- `线条颜色默认使用黑色或深灰单色，不生成彩色描边。`
- `默认输出白底或浅底纯净线稿观感，避免背景干扰主体识别。`
- `透明件、金属件、缝线、接口、边缘转折等关键识别结构应尽量准确保留。`

### 3.6 通用负面约束

以下内容建议所有 `lineartStyle` 共用：

```text
负面约束：不要新增原图中不存在的主体、配件、花纹、文字、Logo、边框、装饰元素或场景内容；不要随意改变主体形状、厚薄、比例、开口方向、连接结构、图案布局和功能部位；不要出现双重轮廓、断裂线、锯齿边、重影、糊线、脏线、大片噪点、无意义排线、结构错位、透视冲突、局部缺失、镜像错误、内容幻觉、背景残影、彩色污渍、水印残留或过度艺术化处理。
```

## 4. 图片理解扩展识别方案

### 4.1 目标

当前多数图片功能只识别 `productCategory`。  
如果希望最终生成结果更稳，仅做品类识别通常不够，建议将图片理解扩展为“品类 + 结构 + 场景 + 风险 + 卖点 + 风格”的分层识别。

这部分的原则是：

- 优先识别会直接影响最终画面生成效果的信息
- 不优先识别只服务投放分析或埋点统计的信息
- 识别结果按“强约束 / 弱约束 / 仅推荐”三层参与后续 prompt

### 4.2 建议新增的识别字段

#### 4.2.1 强相关字段

这些字段建议优先补充，因为会直接影响最终生成效果：

1. `productCategory`
   含义：标准品类
   用途：命中品类规则、决定功能分支、命中结构保护策略

2. `productStructure`
   含义：商品主体的关键结构特征
   示例：`镜头孔`、`开孔边框`、`泵头`、`拉链`、`圆形表盘`、`提手`、`按钮接口`
   用途：决定哪些结构不能被改坏

3. `usageScene`
   含义：当前商品更适合的展示/使用场景
   示例：`桌面展示`、`手持展示`、`上身展示`、`家居空间`、`车载环境`
   用途：决定背景、人物动作、构图和场景合理性

4. `displayRisks`
   含义：容易影响生成稳定性的画面风险点
   示例：`高反光`、`透明材质`、`边框必须完整`、`圆形边界`、`文字必须完整`
   用途：决定负向约束和质量保护规则

5. `sellingPointType`
   含义：商品更适合强调的卖点类型
   示例：`材质质感型`、`结构功能型`、`容量收纳型`、`上身效果型`、`外观颜值型`
   用途：决定镜头重点、细节特写顺序和 prompt 重心

6. `styleDirection`
   含义：更适合的视觉风格方向
   示例：`极简干净`、`生活方式感`、`高级质感`、`科技感`、`可爱轻松`
   用途：决定氛围、色调、背景和构图风格

#### 4.2.2 中相关字段

这些字段对转化表达有帮助，但建议作为弱约束使用：

1. `targetAudience`
   含义：更可能对应的目标人群
   示例：`女性通勤人群`、`学生人群`、`母婴家庭`、`宠物养护人群`
   用途：用于文案润色、氛围偏好、场景推荐

2. `audienceNeed`
   含义：目标人群最可能关注的核心需求
   示例：`便携`、`显质感`、`易收纳`、`舒适`、`耐用`
   用途：用于卖点排序、细节表达和推荐文案

3. `priceTone`
   含义：视觉上更接近的价格带气质
   示例：`平价实用`、`轻奢质感`、`高端专业`
   用途：用于风格调性控制，不建议作为硬约束

#### 4.2.3 低优先级字段

以下字段不建议优先进入生成主链路：

- 投放埋点
- 渠道人群标签
- 广告计划标签
- 运营分发标签

这些更适合用于：

- 推荐排序
- 素材投放分组
- A/B 实验

而不适合作为图片生成 prompt 的主输入。

### 4.4 统一识别提示词（可直接调用）

```text
你是一位电商商品图理解专家。请根据用户上传的商品图片，识别会直接影响后续图片生成效果的关键信息。

识别目标：
1. 识别商品标准品类 `productCategory`。
2. 识别商品关键结构特征 `productStructure`，重点找出不能被改坏的结构。
3. 识别更适合的展示/使用场景 `usageScene`。
4. 识别会影响生成稳定性的展示风险 `displayRisks`。
5. 识别更适合强调的卖点类型 `sellingPointType`。
6. 识别更适合的视觉风格方向 `styleDirection`。
7. 可选识别目标人群 `targetAudience`、核心需求 `audienceNeed` 和价格气质 `priceTone`。

判断要求：
1. 只能基于图片中可见的信息判断，不允许虚构看不见的商品功能。
2. 优先识别会直接影响画面生成效果的信息，不要输出泛营销分析。
3. 若某字段无法稳定判断，可输出空数组或空字符串，不要强猜。
4. `productStructure`、`usageScene`、`displayRisks`、`sellingPointType`、`styleDirection` 各输出 0~3 个最相关结果。
5. `targetAudience`、`audienceNeed` 仅作为弱推断，可为空。

输出要求：
1. 严格输出 JSON，不要输出解释性文字。
2. `confidence` 输出 0~1 的小数，表示整体识别置信度。
3. 所有字段都应服务于后续图片生成 prompt，而不是投放埋点。
```

### 4.5 字段参与最终 Prompt 的建议规则

建议分三层参与：

#### 4.5.1 强约束层

直接进入最终 prompt：

- `productCategory`
- `productStructure`
- `usageScene`
- `displayRisks`

这些字段应参与：

- 品类规则
- 结构保护规则
- 负向约束
- 质量要求

#### 4.5.2 弱约束层

建议进入最终 prompt，但用语应更柔和：

- `sellingPointType`
- `styleDirection`
- `targetAudience`
- `audienceNeed`
- `priceTone`

这些字段适合参与：

- 氛围表达
- 卖点排序
- 风格偏好
- 文案润色

#### 4.5.3 仅推荐层

不直接进入最终 prompt，仅用于推荐或展示：

- 投放标签
- 埋点标签
- 运营渠道标签

### 4.6 推荐的 Prompt 拼装顺序

如果后续图片功能接入扩展识别，推荐按以下顺序消费：

1. 功能主任务目标
2. 品类规则 `productCategory`
3. 结构保护规则 `productStructure`
4. 展示风险与负向约束 `displayRisks`
5. 使用场景约束 `usageScene`
6. 卖点和风格偏好 `sellingPointType + styleDirection`
7. 目标人群与需求弱约束 `targetAudience + audienceNeed + priceTone`
8. 通用质量要求
9. 用户补充描述

### 4.7 导出需求时建议保留的描述

建议在正式需求文档、后端接口文档或流程图中保留以下描述：

> 为提升最终图片生成效果，系统对上传图片的理解不应只停留在品类识别层。建议逐步扩展识别商品关键结构、适配场景、展示风险、卖点类型、风格方向及可选目标人群信息。其中，品类、结构、场景、风险字段优先作为强约束进入最终 prompt；卖点、风格、人群和需求字段作为弱约束参与氛围与表达优化；运营埋点类标签不进入主生成链路。
