## 使用流程
1. 上传商品图（`upload-main`）
2. 选择创作模式（`creation-mode`：普通/高级）
3. 配置高级设置（`advanced-settings`）
4. 填写补充说明（`supplement`，可选）
5. 生成

## 端到端使用流程
1. 用户上传商品图（`upload-main`，最多24张）。
2. 系统执行主体理解、边缘风险和品类识别。
3. 系统触发 AI Assist，回填背景类型、风格与光影。
4. 用户手动修正高级字段并选择输出参数。
5. 若业务链路上已有平台和品类信息，则在最终拼装阶段注入对应规则。
6. 系统组装提示词并生成。

## 2.1 `ruleLevel` 多规则使用逻辑（同一平台存在多条规则时）
适用场景：一个平台可能同时命中“主图规则 + 附图规则 + 品类规则 + 风控规则”。

### 2.1.1 规则定位
+ `ruleLevel=A`：高优先级硬约束，不可被低级规则覆盖。
+ `ruleLevel=B`：常规约束，可被 A 覆盖。
+ `ruleLevel=C`：补充约束，可被 A/B 覆盖，且可在 token 紧张时优先裁剪。

### 2.1.2 组装顺序（强制）
1. 合并所有命中规则的 `required`（去重后全部保留）。
2. 合并所有命中规则的 `forbidden`（去重后全部保留）。
3. `prompt` 按优先级拼接：`A -> B -> C`。
4. 若提示词长度超限，仅从低优先级描述裁剪：先裁 `C.prompt`，再裁 `B.prompt`；`A.prompt`、`required`、`forbidden` 不裁。

### 2.1.3 冲突处理（强制）
+ 若高低级规则存在冲突，按优先级覆盖：`A > B > C`。
+ 对 AI 换背景功能，若平台主图规则与场景化背景冲突，优先保平台硬规则，并将结果降级为附图/场景图语义。

### 2.1.4 比例偏好使用规则（强制）
+ `preferredRatios` 表示该平台下换背景图片默认推荐的比例优先级，按数组从前到后选择。
+ 若用户已显式选择 `ratio`，优先使用用户选择，不被 `preferredRatios` 覆盖。
+ 若用户未显式选择 `ratio`，则按 `preferredRatios[0]` 作为默认比例。
+ 若当前创作模式不支持 `preferredRatios[0]`，则顺延到下一个可用比例。
+ 若平台规则未命中或无比例偏好，则回退到 `全平台通用（16平台）` 的 `preferredRatios`。

## 拼装规则
### 拼装顺序
1. `taskGoal`（任务目标）
2. `categoryRule`（品类规则）
3. `platformRule`（平台规则）
4. `parameterBlock`（参数块）
5. `valuePromptBlock`（字段值扩展约束）
6. `technicalHintBlock`（内部技术提示，可选）
7. `requiredRule`（必须满足）
8. `forbiddenRule`（禁止事项）
9. `universalNegative`（通用负向约束）
10. `universalQuality`（通用质量要求）
11. `platformRuleDetail`（平台细节补充，可选）
12. `supplement`（补充说明，可选）

组装要求：

+ `requiredRule / forbiddenRule / universalNegative / universalQuality` 属于不可裁剪段。
+ token 超限时，优先裁剪 `valuePromptBlock -> platformRule -> supplement -> platformRuleDetail`，不要先裁硬约束。
+ `platformRuleDetail` 仅用于补充业务侧更细的平台限制，不能覆盖平台硬规则。
+ `resolution` 为空时直接省略该字段，不输出空值占位。
+ `technicalHintBlock` 不属于业务显式字段，由图片识别链路内部推断后按固定映射生成；无可靠判断时整段省略，不输出空值占位。
+ `technicalHintBlock` 只能补充光向、材质、反射、阴影、边缘融合要求，不能覆盖 `backgroundType / lightingStyle / platformRule` 的主约束。

### 通用负向约束
```json
通用负向约束：
1. 严禁改变商品主体外观、结构、颜色、材质和SKU含义。
2. 严禁主体边缘毛边、吞边、漂浮感、假倒影和穿帮透视。
3. 严禁在白底主图语境下加入场景道具、营销贴片、Logo、水印或复杂反光。
4. 严禁背景和光影逻辑与商品材质不匹配。
```

### 通用质量说明
```json
通用质量要求：
1. 背景与主体必须自然融合，阴影、反射、色温、透视关系真实一致。
2. 主体完整清晰，边缘干净，空间语义稳定。
3. 背景只增强商品，不得喧宾夺主。
```

```json
3. 背景只增强商品，不得喧宾夺主。
```

## 三个关键能力的提示词配置
### 图片识别获取信息
用途：

+ 识别换背景生成所需的品类、推荐背景类型和光影风格；
+ 输出结构化 JSON，供字段回填和后续提示词组装使用；
+ 判断主体边缘风险、材质反光风险和适合的空间语义，而不是只做泛化商品识别。

提示词：

```json
你是一位电商商品换背景理解专家。请根据输入商品图，提取“换背景生成”所需信息，并严格输出 JSON。

任务要求：
1) 识别商品所属品类（用于 productCategory）。
2) 基于图像线索，预测换背景字段推荐值：backgroundType, lightingStyle。
3) 识别主体受光方向、主体材质线索、材质反光风险、阴影需求和主体边缘风险，供后续拼装内部技术提示使用。
4) `recommendedFields` 中的字段值必须从给定 options 中选择；`technicalHints` 中的字段值必须从下方限定枚举中选择，不允许自由发挥。
5) 不输出解释文字，不输出 Markdown，仅输出 JSON。

输出 JSON Schema：
{

    "categoryId": "string",
    "categoryLabel": "服饰类|鞋靴类|箱包类|珠宝饰品类|美妆个护类|食品饮料类|家居百货类|家电数码类|家具大件类|母婴玩具类|宠物用品类|汽配五金类|通用品类",

  },
  "recommendedFields": {
    "backgroundType": "string",
    "lightingStyle": "string"
  },
  "technicalHints": {
    "lightDirection": "none|left|right|front|back|top|front-left|front-right",
    "materialHints": ["metal|glass|plastic|glossy-plastic|matte-plastic|fabric|wood|paper|ceramic|rubber|leather"],
    "reflectionRisk": "low|medium|high",

  },

}

判定规则：
- 若识别置信度 < 0.70，categoryLabel 输出“通用品类”。
- 若 backgroundType 无可靠依据，优先回填“电商白底”或留空，并加入 needsUserConfirm。
- 若 lightingStyle 无可靠依据，优先回填“写实自然光”或留空，并加入 needsUserConfirm。
- 若 `lightDirection` 无法稳定判断，输出 `none`。
- 若 `materialHints` 无法稳定判断，可返回空数组 `[]` 或仅保留最主要的 1~2 个材质值。

```


内部技术提示字段说明：

+ `lightDirection`（主体受光方向）：用于约束背景主光方向与主体原始受光保持一致。
+ `materialHints`（主体材质线索）：用于约束环境反射、表面高光和背景融合方式。
+ `reflectionRisk`（反光风险）：用于决定是否追加“控制环境映射、避免假反光”的约束。
+ `shadowNeed`（阴影需求）：用于决定是否追加接触阴影或地面阴影要求。
+ `edgeRisk`（边缘风险）：用于决定是否追加边缘净度强化约束。
+ `needsUserConfirm`（需用户确认字段）：用于标记模型没有把握的字段键名；前端或后端可据此决定是否提示用户确认。

+ `lightDirection / reflectionRisk / shadowNeed / edgeRisk` 适合按单值直接映射固定提示词。
+ `materialHints` 适合按多选值分别命中材质提示词，再与 `reflectionRisk` 的风险级别提示词合并生成材质反射控制句。
+ 推荐生成顺序：`lightDirectionPrompt + materialHintPrompts + reflectionRiskPrompt + shadowNeedPrompt + edgeRiskPrompt`，空值对应子句直接跳过。
+ 模型先输出结构化枚举值，后端再按固定映射表生成 `technicalHintPrompt`，不要把枚举值原样裸拼进最终 prompt。
+ `technicalHints` 任一字段未命中可靠值时，只跳过对应子句，不阻塞主流程。

### AI帮写
用途：

+ 在用户点击“AI帮写”时，回填换背景关键字段；
+ 仅输出字段键值，不输出额外解释；
+ 优先给出“主体保真且背景合规”的安全值，而不是激进广告化方案。

提示词：

```json
你是一位商品换背景策划师。请根据商品图片，回填 goods-bg 的关键字段。

必须遵守：
1) 仅返回以下字段：productCategory, backgroundType, lightingStyle。
2) 能确认的字段必须从提供的 options 中选取一个值。
3) 无法确认的字段不要编造，不要猜测，直接留空字符串 ""，并把字段名加入 needsUserConfirm。
4) 若无法判断更复杂场景，backgroundType 优先回填“电商白底”而不是激进广告背景。
5) 若无法判断光影风格，lightingStyle 优先回填“写实自然光”或“柔光棚拍风”。
6) 只输出 JSON，不要输出解释。

输出格式：
{
  "fieldValues": {
    "productCategory": "string",
    "backgroundType": "string",
    "lightingStyle": "string"
  },
  "needsUserConfirm": ["fieldKey1", "fieldKey2"]
}
```

回填策略：

+ 当前前端真实会应用 `backgroundType / lightingStyle`，`productCategory` 可作为隐藏字段回写给拼装层。
+ `productCategory` 可识别、背景/光影无把握时，只回填 `productCategory`，其余字段留空或回填保守默认值。
+ `platformLabel` 不建议仅凭图片强猜，应由上游业务场景注入，不属于本段回填范围。

### 文本润色
用途：

+ 对用户补充说明进行语义增强；
+ 生成可执行、约束清晰、适合换背景模型的补充文本；
+ 自动过滤“高级一点”“自然一点”这类弱约束表达，转成明确的背景、光影、边缘和主体保真要求。

提示词：

```json
你是一位电商换背景文案润色专家。请将下方用户的补充说明优化为“可执行的图像生成约束”，并保持原意。

补充说明：
xxxxxxxxxxxx

润色目标：
1) 强化背景语义、空间关系、光影融合、边缘净度和主体保真。
2) 明确是白底、室内、室外还是广告风，以及希望的光影方向和阴影状态。
3) 避免空泛词，改成可执行描述（背景类型、光源、阴影、反射、主体边缘、不能出现的错误）。
4) 若用户写了可能违规、误导或不真实的要求，自动转为合规表述，不要原样保留。
5) 输出一段最终可直接拼进提示词的文本。

输出要求：
- 仅输出润色后的文本，不要解释。
- 80~180字为宜。
- 不得包含虚构结构、违规Logo/水印、误导性主图替代或与平台规则冲突的表达。
```

默认润色方向：

+ 对 `goods-bg` 来说，重点不应该是“标题文案”或“多视图分工”，而应该是“换什么背景、光从哪里来、主体边缘如何处理、主体与背景怎么自然融合”。
+ 若用户未明确写背景类型，润色时优先补成“背景简洁、服务主体、光影与原商品材质一致”这类保守表达。

## 结论
AI换背景真正要解决的是“换背景但不换主体”，核心是边缘、光影、场景和平台语义一起成立。
