# 创作记录右侧侧栏模块需求文档

## 1. 文档说明

- 模块名称：`创作记录右侧侧栏`
- 对应实现：
  - [src/App.tsx](/Users/zhaowenwen/CODEX/CKTAI电商/src/App.tsx)
  - 侧栏组件：`TaskHistoryRail`
  - 联动结果区组件：`ResultPanel`
  - 全局创作页组件：`MyCreationPage`
- 文档目标：输出该模块的产品需求、交互流程、数据结构、状态流转、异常处理与开发建议，便于前后端直接落地

## 2. 模块定位

该模块位于工作台页面最右侧，为一个可展开/收起的窄侧栏，用于承载“当前功能”的创作记录列表。

它的核心价值不是单纯展示历史任务，而是承担以下职责：

1. 快速回看当前功能历史任务
2. 在多次生成之间快速切换任务上下文
3. 联动左侧配置区与中间结果区恢复任务现场
4. 在窄空间中提供任务进度总览

可理解为：`当前工具维度的轻量任务时间线 + 快速上下文恢复入口`

## 3. 适用范围

该模块只出现在 `workspace` 工作台场景下，不出现在“我的创作”汇总页。

页面结构关系：

1. 左侧一级导航
2. 左侧二级工具菜单
3. 中间配置面板 `ConfigPanel`
4. 中间结果面板 `ResultPanel`
5. 最右创作记录侧栏 `TaskHistoryRail`

## 4. 模块目标

### 4.1 用户目标

- 快速看到当前功能最近的生成记录
- 不进入“我的创作”也能切换历史任务
- 一眼知道哪些任务还在生成中
- 点击某条记录后，恢复当次任务的素材、补充说明、结果图

### 4.2 业务目标

- 提高结果复看率
- 提高二次下载率
- 提高同工具复用率
- 降低“找不到刚刚生成内容”的用户困惑

## 5. 页面结构

## 5.1 展开态结构

展开态侧栏包含：

1. 收起按钮
2. 头部信息区
3. 任务列表区

### 头部信息区

包含字段：

- 标题：`创作记录`
- 进行中数量：`进行中 N`

说明：

- 当 `activeCount = 0` 时该文案可为空

### 任务列表区

每组包含：

1. 日期标题

## 5.2 收起态结构

- 仍需要让用户感知到“还有任务在跑”

## 6. 数据结构

## 6.1 任务记录主结构 `TaskRecord`

当前实现中的任务记录结构如下：

```ts
type TaskRecordStatus = "queued" | "generating" | "completed";

type TaskRecord = {
  id: string;
  toolKey: string;
  taskId: string;
  createdAt: number;
  totalCount: number;
  successCount: number;
  failCount: number;
  status: TaskRecordStatus;
  itemIds: string[];
  coverSrcs: string[];
  snapshot: {
    mainUploads: UploadItem[];
    referenceUploads: UploadItem[];
    videoUploads?: UploadItem[];
    advancedSelections: AdvancedSelectionMap;
    supplementValue: string;
    creationModeSelection: CreationModeSelection | null;
  };
};
```

## 6.2 任务记录字段解释

- `id`：任务记录唯一 ID
- `toolKey`：所属工具，如 `set-main`、`goods-marketing`
- `taskId`：任务号，面向展示与任务追踪
- `createdAt`：创建时间时间戳
- `totalCount`：本次任务总生成项数
- `successCount`：已成功数
- `failCount`：已失败数
- `status`：任务整体状态
- `itemIds`：该任务关联的结果项 ID 列表
- `coverSrcs`：用于侧栏预览的封面图，最多 4 张
- `snapshot`：任务快照，用于恢复当次生成配置

## 6.3 结果项结构 `ResultItem`

结果区联动依赖的结果项结构：

```ts
type ResultItemStatus = "skeleton" | "queued" | "generating" | "ready" | "failed";

type ResultItem = {
  id: string;
  toolKey: string;
  label: string;
  fileName: string;
  taskId: string;
  mediaKind: "image" | "video";
  status: ResultItemStatus;
  src?: string;
  selected: boolean;
  createdAt: number;
  roleLabel?: string;
  overlayText?: string;
};
```

## 7. 状态定义

## 7.1 任务状态

任务层状态：

1. `queued`
2. `generating`
3. `completed`

状态说明：

- `queued`：任务刚提交，还没有开始完成任一结果项
- `generating`：至少一个结果项开始生成，但整体未全部完成
- `completed`：成功 + 失败 数量之和达到总数

## 7.2 结果项状态

结果项层状态：

1. `skeleton`
2. `queued`
3. `generating`
4. `ready`
5. `failed`

关系说明：

- 任务侧栏看的是任务聚合状态
- 结果区看的是单个结果项状态

## 7.3 侧栏显示状态

侧栏自身状态：

1. 展开态
2. 收起态
3. 空态

## 8. 展示规则

## 8.1 数据范围规则

侧栏只展示“当前工具”的任务记录，不展示其他工具记录。

例如：

- 当前工具为 `set-main`，侧栏仅显示 `taskRecordsByTool["set-main"]`
- 当前切到 `goods-scene`，侧栏切换为该工具对应记录

## 8.2 时间分组规则

任务按 `createdAt` 格式化为日期后分组显示。

分组结构：

1. 日期标题
2. 该日期下的任务卡片列表

示例：

```text
2026-04-27
  [任务卡1] [任务卡2]
2026-04-26
  [任务卡3]
```

## 8.3 卡片预览规则

每个任务卡片只展示视觉缩略，不展示完整文字元信息。

预览区逻辑：

- `coverSrcs.length = 0`
  展示占位块
- `coverSrcs.length = 1`
  展示单张封面图
- `coverSrcs.length > 1`
  展示拼图样式，最多 4 张

## 8.4 卡片角标规则

角标位于缩略预览图上层。

显示逻辑：

- 任务未完成时：
  - 显示 loading spinner
  - 文案为 `已完成数/总数`
  - 代码逻辑为 `successCount + failCount / totalCount`
- 任务已完成时：
  - 显示 `+总数`

说明：

- 已完成任务当前不区分“全成功完成”还是“部分失败但流程结束”
- 只要任务状态为 `completed`，角标统一显示 `+N`

## 8.5 当前选中态

当某任务被点击选中后：

- 任务卡片高亮
- 高亮判断条件：`selectedTaskId === record.taskId`

## 8.6 空态规则

当前工具无任务记录时，展示：

`当前功能暂无任务记录`

### 收起操作

用户点击展开态顶部的收起按钮：

- 侧栏进入收起态
- 中间内容区获得更大宽度
- 不影响当前结果区与配置区内容

### 展开操作

### 收起态徽标

当 `activeCount > 0` 时：

- 在收起态按钮上显示进行中数量徽标

## 9.2 点击任务卡

点击某一条任务卡时，执行以下联动：

1. 切回 `workspace`
2. 切换到该任务所属工具
3. 将该任务设置为当前选中任务
4. 结果区切换到 `results`
5. 将任务快照中的上传素材恢复到表单
6. 将补充说明恢复到当前工具输入区

对应实现入口：

- `handleSelectTaskRecord(record)`

恢复内容包括：

```ts
mainUploads
referenceUploads
videoUploads
supplementValue
selectedTaskId
resultTab
```

说明：

- 当前实现会恢复素材和补充说明
- 高级设置是否完整恢复，依赖 `restoredTask` 再由各子表单 useEffect 回填

## 9.3 与结果区联动

点击任务卡后，结果区会展示该任务关联的结果项。

联动方式：

- 当前结果区数据本身是按 `toolKey` 维度管理
- 选中任务后，结果区仍显示当前工具下全部结果项
- 但 `selectedTaskId` 会用于：
  - 标识当前任务
  - 支持智能标题等任务级操作

说明：

- 当前实现不是“只过滤出该任务的结果项”
- 而是“在当前工具的结果池中选中该任务上下文”
- 如果后续产品要求更强的任务隔离，需新增任务级结果过滤能力

## 9.4 结果区反向联动

在“我的创作-结果图”中点击某个结果项时，也会反向定位到：

1. 工作台
2. 对应工具
3. 对应任务
4. 对应结果页签

说明：

- 这是创作记录体系的一部分
- 右侧侧栏与“我的创作”共用同一任务选择逻辑

## 10. 任务生成流转

## 10.1 提交任务后

用户点击生成并校验通过后：

1. 创建 `taskId`
2. 创建 `TaskRecord`
3. 写入 `taskRecordsByTool[tool.key]`
4. 创建若干 `ResultItem`
5. 写入 `resultItemsByTool[tool.key]`
6. 默认选中当前新任务

默认初始任务记录：

- `status = "queued"`
- `successCount = 0`
- `failCount = 0`
- `coverSrcs = []`

## 10.2 单结果开始生成

当某个结果项进入生成中：

- 结果项状态从 `queued/skeleton` 进入 `generating`
- 任务记录状态进入 `generating`

## 10.3 单结果完成

当某个结果项完成时：

- 若成功：
  - `successCount + 1`
  - 若有 `src`，插入 `coverSrcs`
  - `coverSrcs` 最多保留 4 张
- 若失败：
  - `failCount + 1`

任务状态判断：

- `successCount + failCount >= totalCount` 时置为 `completed`
- 否则保持 `generating`

## 10.4 删除结果对任务的影响

删除结果项或取消排队后，需要同步修正任务记录：

1. `totalCount - 1`
2. 从 `itemIds` 中移除对应结果项
3. 若结果成功图被删，从 `coverSrcs` 中移除
4. 重新计算 `successCount / failCount / status`
5. 若任务已无结果项，则整条任务记录删除

## 15. 边界规则

## 15.1 当前工具无任务

- 侧栏空态文案：`当前功能暂无任务记录`

## 15.2 当前工具切换

- 切换工具后，侧栏应切到该工具的任务记录
- 若该工具无结果，结果区默认可切到 `cases`

## 15.3 删除任务最后一项

- 若该任务最后一个结果项被删除或取消
- 任务记录整体删除
- 若当前选中的是该任务，选中态清空

## 15.4 已完成但包含失败项

当前实现中：

- 只要成功数 + 失败数 = 总数
- 任务就被视为 `completed`

这意味着：

- “完成”不等于“全成功”
- 若后续需要区分，建议补充 `partially_failed` 状态

## 15.5 结果区未按任务过滤

当前实现中：

- 结果区是“当前工具的所有结果项池”
- 不是“当前选中任务的纯净结果列表”

这是当前最大一个产品与开发边界点，建议尽快确认：

1. 方案 A：保留现状，只标记当前任务
2. 方案 B：切换任务时，结果区仅显示该任务结果

如果要提升任务语义清晰度，建议采用方案 B。

## 19. 当前实现风险与建议

## 19.1 任务与结果区关联不够强

建议增加按 `selectedTaskId` 过滤当前结果区结果项的能力，否则历史任务切换后用户容易看到混合结果。

## 19.2 已完成状态语义过粗

建议把任务状态扩展为：

1. `queued`
2. `generating`
3. `completed`
4. `completed_with_failures`

## 19.3 任务卡信息偏弱

当前侧栏只展示缩略图，没有展示任务号、时间或工具信息。若任务量大，检索效率会下降。建议支持 hover 或 tooltip 补充任务基础信息。

## 19.4 结果数量角标不够直观

当前已完成任务显示 `+N`，不能直观看出成功/失败分布。建议改为：

- 全成功：`N/N`
- 含失败：`成功N / 失败M`

## 20. 结论

“创作记录右侧侧栏”不是一个简单的视觉挂件，而是工作台中的任务上下文切换器。开发落地时，必须把它与以下三件事一起实现：

1. 任务快照存储与恢复
2. 结果区的任务联动
3. 任务状态与结果状态的双层同步

如果只实现一个静态列表，用户的核心价值无法成立。该模块应按“轻量任务中心”思路来做，而不是普通侧边栏。
