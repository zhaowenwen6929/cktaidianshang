# 商品白底图提示词与配置方案

## 1. 目标

本文档单独整理“商品白底图”能力的提示词拼装逻辑与落地配置，覆盖以下业务流程：

1. 用户上传商品图
2. AI 识别商品品类
3. 用户选择目标平台
4. 系统按“品类信息 + 平台规则 + 白底图通用规范”组合最终提示词
5. 生成可直接上架的合规商品白底图

适用平台统一覆盖：

- 淘宝
- 天猫
- 京东
- 拼多多
- 1688
- 抖音电商
- 快手电商
- 小红书电商
- 亚马逊
- Temu
- TikTok Shop
- 阿里国际站
- 速卖通
- Shopee
- OZON
- SHEIN

## 2. 推荐使用流程

### 2.1 用户侧流程

1. 上传商品图
2. 系统识别商品主体与品类
3. 用户选择目标平台
4. 系统自动带出平台白底规则
5. 系统拼装最终提示词
6. 调用白底图模型生成结果

### 2.2 系统侧核心原则

- 品类识别负责补充“商品是什么”
- 平台选择负责补充“要遵守什么规则”
- 白底通用规则负责约束“最终画面必须长什么样”
- 最终提示词必须是结构化拼接，而不是只依赖一段自由描述

## 3. 提示词结构

与代码实现一致，最终提示词由 7 段组成：

1. 任务目标段
2. 商品信息段（品类）
3. 平台要求段
4. 平台规则段
5. 白底规则段（全局）
6. 品类规则段
7. 补充要求段（可选）

推荐拼接公式如下：

```text
{任务目标}
{商品信息}
{平台要求}
{平台规则}
{白底规则}
{品类规则}
{补充要求(可选)}
```

补充约束（与 `buildGoodsWhitePromptWithMeta` 一致）：

- 段落顺序固定，使用 `\n\n` 连接。
- `补充要求` 仅在 `extraDetails` 非空时拼接。
- `strict=true` 时：平台规则/品类规则未命中直接报错，不走静默兜底。
- `strict=false` 时：平台规则未命中回退 `goodsWhiteUniversalPresetConfig.prompt`，品类规则未命中回退通用品类兜底文案，保证可生成。

## 4. 最终提示词模板

以下为推荐的最终生成提示词模板：

```text
任务目标：请基于上传的商品原图，生成适用于电商平台上架的合规商品白底主图。

商品信息：当前商品品类为「{productCategory}」。请确保保留该品类商品应有的真实结构、材质、颜色、纹理、比例关系与细节特征，禁止错误改造商品形态，禁止替换商品主体。

平台要求：目标平台为「{platformLabel}」。请优先满足该平台对商品主图/白底图的通用规范，确保画面适合平台首图展示与直接上架使用。

平台规则：{platformRulePrompt}

白底规则：输出纯白背景（RGB 255,255,255），仅保留实际售卖商品主体，不添加人物、手模、道具、文字、水印、Logo、边框、贴纸、价格标签、营销角标或任何其他促销元素；商品主体完整居中，边缘清晰锐利，不截断、不缺角、不拉伸、不变形；默认仅允许非常轻微且自然的接触阴影，禁止明显投影；保留商品真实颜色、材质、纹理、透明件、金属件与高反光细节，不过曝，不过暗，不过度磨皮，不过度锐化，不得使用与实物不符的渲染替代图；最终输出为真实、专业、干净、可直接上架的标准商品白底图。

品类规则：{categoryRulePrompt}

补充要求：{extraDetails}
```

说明（与代码一致）：

- 第 4 节模板与 `buildGoodsWhitePromptWithMeta` 的实际拼接段保持一一对应。  
- 示例中的“白底规则”来源：`src/config/goodsWhitePromptConfig.ts` 中的 `goodsWhiteGlobalRulePrompt`（通过 `goodsWhitePromptComposerConfig.globalRulePrompt` 引用）。

## 5. 全平台通用白底规则

当用户选择“全平台通用（16平台）”时，直接使用以下规则段：

```text
任务目标：生成适用于多平台上架的全品类商品标准白底主图。适用平台：淘宝、天猫、京东、拼多多、1688、抖音电商、快手电商、小红书电商、亚马逊、Temu、TikTok Shop、阿里国际站、速卖通、Shopee、OZON、SHEIN。背景要求：纯白背景（RGB 255,255,255），画面干净通透，不出现色偏、杂色、背景纹理或场景元素。主体要求：仅保留商品主体，主体完整居中，边缘清晰锐利，不截断、不缺角、不拉伸、不变形，主体占画面合理比例，适合主图陈列。合规要求：不添加人物、手模、道具、文字、水印、Logo、边框、贴纸、价格标签、促销角标或任何营销信息。光影要求：允许非常轻微且自然的接触阴影或弱倒影，用于体现悬浮感与立体感，但不能影响白底纯净度和平台合规性。质感要求：保留商品真实颜色、材质、纹理、透明件、金属件、高反光细节与结构层次，不过曝，不过暗，不过度磨皮，不过度锐化。输出要求：整体呈现为真实、专业、可直接上架的电商商品白底图，避免风格化背景、夸张特效和非商品信息干扰。
```

## 6. 品类识别配置

### 6.1 目的

品类识别不是为了替用户决定平台，而是为了让最终提示词更准确地描述商品本体。

### 6.2 推荐字段

```ts
type GoodsWhiteCategoryRecognition = {
  // 品类英文 ID，建议 kebab-case，便于程序判断和统计
  categoryId: string;
  // 品类中文名称，用于提示词拼装和前端展示
  categoryLabel: string;
  // 识别置信度，0~1
  confidence: number;
  // 识别依据关键词，来自视觉线索
  keywords: string[];
};
```

### 6.3 推荐输出示例

```ts
{
  categoryId: "home-appliance",
  categoryLabel: "小家电",
  confidence: 0.92,
  keywords: ["电器", "塑料外壳", "按键", "家用"]
}
```

### 6.4 提示词中的使用方式

系统只需要拿 `categoryLabel` 参与最终提示词拼接：

```text
商品信息：当前商品品类为「小家电」。
```

### 6.5 品类识别完整提示词（可直接调用）

```text
你是一位电商商品图理解与品类识别专家。
你的任务是：根据上传商品图识别最可能的商品品类，并输出结构化 JSON 结果，供白底图提示词拼装使用。
请只基于图片可见信息判断，不要猜测品牌或不存在的功能。
如果图片信息不足，请输出通用品类并降低置信度。

输出字段要求：
1) categoryId: 英文短 ID，使用 kebab-case，例如 home-appliance、fashion-top、shoes-sneakers。
2) categoryLabel: 中文品类名，必须可读，例如 小家电、服饰类、鞋靴类、箱包类。
3) confidence: 0 到 1 的小数，保留两位。
4) keywords: 3~8 个关键词，描述你判断该品类的视觉依据，例如 材质、结构、部件。

输出格式要求：
1) 只输出 JSON，不要输出解释文字。
2) 必须包含 categoryId、categoryLabel、confidence、keywords 四个字段。
3) keywords 必须是字符串数组。

当无法确定具体品类时：
categoryId 使用 general-merchandise，categoryLabel 使用 通用品类，confidence 不高于 0.55。
```

### 8.3 运行时拼接函数示例

```ts
function buildGoodsWhitePrompt(params: {
  // AI 识别出的品类中文名，如：小家电、鞋靴类
  productCategory: string;
  // 用户选择的平台名称，如：亚马逊、TikTok Shop、全平台通用（16平台）
  platformLabel: string;
  // 可选：平台专项规则覆盖文案，不传则用内置平台规则
  platformRulePrompt?: string;
  // 可选：用户补充要求
  extraDetails?: string;
}) {
  const taskPrompt = "请基于上传的商品原图，生成适用于电商平台上架的合规商品白底主图。";
  const productPrompt = `当前商品品类为「${params.productCategory}」。请确保保留该品类商品应有的真实结构、材质、颜色、纹理、比例关系与细节特征，禁止错误改造商品形态，禁止替换商品主体。`;
  const platformPrompt = `目标平台为「${params.platformLabel}」。请优先满足该平台对商品主图/白底图的通用规范，确保画面适合平台首图展示与直接上架使用。`;
  const platformRulePrompt =
    params.platformRulePrompt ??
    "（这里读取平台配置中的 prompt，例如亚马逊平台规则或全平台通用规则）";
  const globalRulePrompt =
    "输出纯白背景（RGB 255,255,255），仅保留商品主体，不添加人物、手模、道具、文字、水印、Logo、边框、贴纸、价格标签、营销角标或任何促销信息；主体完整居中，边缘清晰锐利，不截断、不缺角、不拉伸、不变形；允许非常轻微且自然的接触阴影或弱倒影，以增强立体感，但不能影响白底纯净度与平台合规性；保留商品真实材质、颜色、纹理、透明件、金属件和高反光细节，不过曝，不过暗，不过度磨皮，不过度锐化；整体输出为真实、专业、干净、可直接上架的标准电商白底商品图。";
  const categoryRulePrompt =
    "（这里读取品类配置中的 prompt，例如鞋靴类结构保护、珠宝高光保护等）";
  const extraDetailsPrompt = params.extraDetails?.trim() ? `补充要求：${params.extraDetails.trim()}` : "";

  return [taskPrompt, productPrompt, platformPrompt, platformRulePrompt, globalRulePrompt, categoryRulePrompt, extraDetailsPrompt]
    .filter(Boolean)
    .join("\n\n");
}
```

## 9. AI 辅助识别配置

如果需要让 AI 在上传后自动回填平台或推荐“全平台通用（16平台）”，可使用如下辅助提示词：

```text
你是一位电商商品白底图顾问。目标是为全品类商品提供统一适配的白底主图能力，优先覆盖淘宝、天猫、京东、拼多多、1688、抖音电商、快手电商、小红书电商、亚马逊、Temu、TikTok Shop、阿里国际站、速卖通、Shopee、OZON、SHEIN。请先判断商品是否已经出现明确的平台线索：若能明确识别，则仅回填对应“平台信息”字段；若无法从商品图判断具体平台，请优先回填“全平台通用（16平台）”，表示采用跨平台统一白底图规范。回填时不要编造其他字段，不要输出额外解释。
```

## 10. 最终建议

- 文案层面不要只保留“白底、干净、主体突出”这类弱描述，必须保留禁止项、阴影限制、真实材质约束。
- 配置层面建议把“平台列表”“统一规则提示词”“最终拼接模板”拆开管理，避免后续多个页面重复维护。
- 如果后续要继续增强，可以再增加“按品类补充约束”的第二层规则，例如服饰、珠宝、透明器皿、家电、食品的材质和边缘细节要求。

### 14.5 示例拆解与拼接规则对齐（严格对应代码）

本示例严格按 `buildGoodsWhitePromptWithMeta` 的 7 段顺序拼接（使用 `\n\n` 连接）：

1. `任务目标` ← `goodsWhitePromptComposerConfig.taskPrompt`
2. `商品信息` ← `goodsWhitePromptComposerConfig.productPromptTemplate`
3. `平台要求` ← `goodsWhitePromptComposerConfig.platformPromptTemplate`
4. `平台规则` ← `goodsWhitePlatformRuleConfigs[label=淘宝].prompt`
5. `白底规则` ← `goodsWhitePromptComposerConfig.globalRulePrompt`
6. `品类规则` ← `goodsWhiteCategoryRuleConfigs[label=服饰类].prompt`
7. `补充要求` ← 输入参数 `extraDetails`（非空时拼接）

说明：

- `任务目标：/商品信息：/平台要求：/平台规则：/白底规则：/品类规则：` 这些标题是文档展示层标签；实际代码中对应的是同一段原文内容。
- 严格模式下不应出现任何未在上述配置来源中的额外文案。
