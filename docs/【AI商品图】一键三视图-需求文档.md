1. 上传商品图（`upload-main`）
2. 选择拍摄视角（`camera-angle`）
3. 选择创作模式（`creation-mode`：普通/高级）
4. 配置高级设置（`advanced-settings`）
5. 生成

## 端到端使用流程
1. 用户上传商品图（`upload-main`，最多24张）。
2. 用户选择拍摄视角方案（单视角或品类预设三视图）。
3. 系统可结合图片理解识别商品品类，补充视角预设和平台约束。
4. 用户选择创作模式参数（`modeId` / `ratio` / `resolution` / `count`）。
5. 用户配置平台信息，必要时补充平台细节规则。
6. 系统按 strict 规则组装最终提示词并提交生成。

## 2.1 `ruleLevel` 多规则使用逻辑（同一平台存在多条规则时）
适用场景：一个平台可能同时命中“平台基础规则 + 图位规则 + 品类规则 + 风控规则”。

### 2.1.1 规则定位
+ `ruleLevel=A`：高优先级硬约束，不可被低级规则覆盖。
+ `ruleLevel=B`：常规约束，可被 A 覆盖。
+ `ruleLevel=C`：补充约束，可被 A/B 覆盖，且可在 token 紧张时优先裁剪。

### 2.1.2 组装顺序（强制）
1. 合并所有命中规则的 `required`（去重后全部保留）。
2. 合并所有命中规则的 `forbidden`（去重后全部保留）。
3. `prompt` 按优先级拼接：`A -> B -> C`。
4. 若提示词长度超限，仅从低优先级描述裁剪：先裁 `C.prompt`，再裁 `B.prompt`；`A.prompt`、`required`、`forbidden` 不裁。

### 2.1.3 冲突处理（强制）
+ 若高低级规则存在冲突，按优先级覆盖：`A > B > C`。
+ 对三视图功能，若平台主图规则与后两张补充视图语义冲突，优先保首视图平台硬规则，第二、第三视图继续承担结构补充职责。

### 2.1.4 比例偏好使用规则（强制）
+ `preferredRatios` 表示该平台下三视图默认推荐的比例优先级，按数组从前到后选择。
+ 若用户已显式选择 `ratio`，优先使用用户选择，不被 `preferredRatios` 覆盖。
+ 若用户未显式选择 `ratio`，则按 `preferredRatios[0]` 作为默认比例。
+ 若当前创作模式不支持 `preferredRatios[0]`，则顺延到下一个可用比例。
+ 若平台规则未命中或无比例偏好，则回退到 `全平台通用（16平台）` 的 `preferredRatios`。

## 拼装规则
### 拼装顺序
1. `taskGoal`（任务目标）
2. `modeRule`（模式规则）
3. `platformRule`（平台规则）
4. `categoryRule`（品类规则）
5. `cameraAnglePrompt`（拍摄视角扩展）
6. `platformInfoValuePrompt`（平台信息扩展）
7. `parameterLine`（参数行）
8. `requiredRule`（必须满足）
9. `forbiddenRule`（禁止事项）
10. `universalNegative`（通用负向约束）
11. `universalQuality`（通用质量要求）
12. `platformRuleDetail`（平台细节补充，可选）

组装要求：

+ `requiredRule / forbiddenRule / universalNegative / universalQuality` 属于不可裁剪段。
+ token 超限时，仅允许按 `platformRuleDetail -> platformInfoValuePrompt -> categoryRule -> platformRule` 顺序裁剪。
+ `platformRuleDetail` 仅作为补充说明，不能覆盖平台硬约束。
+ `resolution` 为空时直接省略该字段，不输出空值占位。

### AI帮写
用途：

+ 在用户点击“AI帮写”时，回填三视图关键字段；
+ 仅输出字段键值，不输出额外解释；
+ 优先给出“有助于视角职责清晰、三图一致”的安全值，而不是无依据的复杂角度组合。

提示词：

```json
你是一位商品三视图策划师。请根据商品图片，回填 goods-view 的关键字段。

必须遵守：
1) 仅返回以下字段：platformInfo, productCategory, cameraAngle。
2) 能确认的字段必须从提供的 options 中选取一个值。
3) 无法确认的字段不要编造，不要猜测，直接留空字符串 ""，并把字段名加入 needsUserConfirm。
4) productCategory 若无法确定，优先回填“通用品类”。
5) cameraAngle 若无法确定，优先回填“电商通用（不规则或结构复杂类）”而不是激进角度组合。
6) 只输出 JSON，不要输出解释。

输出格式：
{
  "fieldValues": {
    "platformInfo": "string",
    "productCategory": "string",
    "cameraAngle": "string"
  },
  "needsUserConfirm": ["fieldKey1", "fieldKey2"]
}
```

回填策略：

+ `productCategory` 可以识别、`cameraAngle` 无把握时，只回填 `productCategory`，`cameraAngle` 留空或回填 `电商通用（不规则或结构复杂类）`。
+ `platformInfo` 一般不建议仅凭图片强猜；若没有上游上下文，优先回填 `无平台信息` 并加入 `needsUserConfirm`。
+ 当前前端默认不展示 `AI帮写` 入口，但服务端或后续版本接入时，可直接复用本段协议。

### 文本润色
用途：

+ 对后续若启用的补充说明进行语义增强；
+ 生成可执行、约束清晰、适合三视图模型的补充文本；
+ 自动过滤“多几个角度”“好看一点”这类弱约束表达，转成明确的视角和一致性要求。

提示词：

```json
你是一位电商三视图文案润色专家。请将下方用户的补充说明优化为“可执行的图像生成约束”，并保持原意。

补充说明：
xxxxxxxxxxxx

润色目标：
1) 强化三张图的视角分工、首视图职责、后两图的信息增量和跨视图一致性。
2) 明确是偏正面/侧面/背面/底部/顶部/45度补充中的哪种组合。
3) 避免空泛词，改成可执行描述（首图职责、后续图职责、背景、结构一致性、不能出现的错误）。
4) 若用户写了可能违规、误导或不真实的要求，自动转为合规表述，不要原样保留。
5) 输出一段最终可直接拼进提示词的文本。

输出要求：
- 仅输出润色后的文本，不要解释。
- 80~180字为宜。
- 不得包含虚构结构、重复视角、违规Logo/水印、误导性主图替代或与平台规则冲突的表达。
```

默认润色方向：

+ 对 `goods-view` 来说，重点不应该是“局部工艺”或“标题层级”，而应该是“首图承担什么、第二第三图补什么、三张图如何保持一致”。
+ 若用户未明确写三张图分工，润色时优先补成“首图负责商品识别，第二图补侧面或厚度，第三图补背面、底部或关键结构面”这类保守表达。

## 结论
一键三视图真正要解决的是“多视图一致性”和“视角职责分工”，不是简单多出两张角度图。
