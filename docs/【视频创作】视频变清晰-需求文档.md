# 【视频创作】视频变清晰-需求文档

## 需求目标
用户输入：

1. 上传 1 条待增强视频
2. 选择清晰化输出规格（原画增强 / 2K / 4K）

系统输出：

+ 基于原视频内容输出 1 条清晰度增强后的视频
+ 尽量保留原视频构图、节奏、主体动作和原始比例
+ 提升主体细节、边缘锐度、画面纯净度和整体稳定性

## 核心逻辑
视频变清晰不是重生成视频，也不是补拍镜头能力。当前真实链路更接近“原视频增强处理”，执行口径如下：

1. 读取原视频主体内容与原始比例
2. 根据用户选择的输出规格执行清晰度增强
3. 保留原视频镜头节奏、画面结构和主体动作
4. 输出 1 条增强后的视频结果

## 使用流程
1. 上传视频（`upload-video`）
2. 选择增强规格（`video-clarify-resolution`）
3. 生成

## 端到端使用流程
1. 用户上传 1 条视频，作为唯一处理对象。
2. 系统保留原视频比例，不提供裁切、补帧或改脚本能力。
3. 用户在分辨率区选择 `原画增强 / 2K / 4K`。
4. 系统按当前增强模式执行清晰化处理，返回 1 条结果视频。

## 2. 清晰化参数

### 2.1 字段与可选值

```json
{
  "videoClarifyFields": {
    "videoClarifyResolution": ["原画增强", "2K", "4K"]
  }
}
```

说明：

+ `videoClarifyResolution` 是当前页面唯一显式参数
+ `ratio` 固定为 `原视频比例`
+ `count` 固定为 `1`

### 2.2 参数语义

1. `原画增强`
   以尽量保持原视频输出规格为前提，优先提升细节、锐度和纯净度。
2. `2K`
   输出目标为 2K 增强结果。
3. `4K`
   输出目标为 4K 增强结果。

实现要求：

+ 需求文档中应把该能力表述为“增强”而非“重制”
+ 不应承诺当前页面具备修复剧情、改镜头、重做字幕等超出增强范畴的能力

## 3. 最终处理原则

视频变清晰最终处理指令至少应包含以下信息层：

1. 任务目标：提升原视频清晰度
2. 原视频约束：保持原视频比例、构图和节奏
3. 输出规格：原画增强 / 2K / 4K
4. 通用质量约束：减少噪点、避免闪烁、保持主体边缘自然

### 3.1 推荐处理指令骨架

```text
你是一位视频增强与画质优化专家。

任务目标：基于用户上传的原视频，输出 1 条增强后的视频结果。

原视频约束：
1. 保持原视频构图、主体动作、镜头节奏与原始比例不变。
2. 不擅自新增镜头、删减镜头或改写原视频内容。

输出规格：
目标分辨率={videoClarifyResolution}；
输出比例=原视频比例；
输出数量=1。

质量要求：
1. 优先提升主体细节、边缘锐度和画面纯净度。
2. 控制过度锐化、局部噪点和帧间闪烁。
3. 保持人物、商品、字幕边缘和高频细节稳定自然。
```

## 4. 与相邻功能的边界

### 4.1 与 `video-remove-bg` 的边界

- `video-clarify`：提升原视频清晰度与纯净度
- `video-remove-bg`：分离原视频主体与背景

### 4.2 与 `video-watermark` 的边界

- `video-clarify`：不以去除水印或字幕为主目标
- `video-watermark`：核心是去除水印、字幕或角标

### 4.3 与 `video-translate` 的边界

- `video-clarify`：不处理语音/字幕翻译
- `video-translate`：核心是语音、文字或字幕翻译
