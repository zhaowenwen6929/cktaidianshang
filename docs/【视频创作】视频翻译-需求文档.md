# 【视频创作】视频翻译-需求文档

## 需求目标
用户输入：

1. 上传 1 条待翻译视频
2. 选择翻译模式
3. 选择目标语言
4. 补充翻译要求

系统输出：

+ 输出 1 条处理后的视频翻译结果
+ 保持原视频比例、节奏和主体内容稳定
+ 尽量保证语义准确、语气自然和字幕时间轴匹配

## 核心逻辑
视频翻译不是视频重拍能力，当前更接近“语音/文字识别 + 翻译 + 字幕映射”的视频处理能力。执行链路如下：

1. 读取原视频比例、语音或画面文字内容
2. 根据模式决定处理对象是语音、字幕文字，还是语音字幕提取
3. 按目标语言执行翻译或提取
4. 将翻译结果映射回视频处理结果中
5. 输出 1 条翻译后视频

## 使用流程
1. 上传视频（`upload-video`）
2. 选择翻译模式（`video-translate-mode`）
3. 选择目标语言（`target-language`）
4. 填写翻译要求（`supplement`）
5. 生成

## 端到端使用流程
1. 用户上传 1 条视频。
2. 用户选择翻译模式。
3. 用户选择目标语言。
4. 用户补充翻译要求，例如保留原节奏、适配跨境电商语气等。
5. 系统完成识别、翻译与结果映射，返回 1 条处理结果视频。

## 功能基础说明

### 1.1 功能定位

- 功能名称：`视频翻译`
- 工具 Key：`video-translate`
- 所属一级分组：`视频创作`
- 能力定位：对原视频中的语音、字幕或文字内容做翻译处理

### 1.2 当前真实页面结构

- `creationModeConfigKey`：`video-processing`
- `sectionOrder`：`["upload-video", "video-translate-mode", "target-language", "supplement"]`
- 上传区：
  - 视频：最多 `1` 条，必填
- 当前页面不展示单独的普通/高级模式切换 UI

补充说明：

+ `supplement` 在本功能中真实可见，标签应理解为“翻译要求”
+ `video-processing` 配置层存在 `普通模式 / 高级模式`，但当前页面未显式暴露

## 3. 最终处理原则

视频翻译最终处理指令至少应包含以下信息层：

1. 任务目标：翻译原视频中的语音或文字内容
2. 模式信息：翻译视频语音 / 翻译视频文字、字幕 / 提取语音字幕
3. 目标语言：指定翻译语言
4. 原视频约束：保持原视频比例、节奏和主体内容
5. 质量约束：翻译准确、语气自然、时间轴稳定

### 3.1 推荐处理指令骨架

```text
你是一位视频字幕翻译与跨语言内容适配专家。

任务目标：基于用户上传的视频，按指定模式完成语音或文字翻译，并输出 1 条处理后视频。

翻译模式：
当前模式={videoTranslateMode}；
目标语言={targetLanguage}。

原视频约束：
1. 保持原视频比例、主体内容、镜头节奏不变。
2. 不破坏原视频中的主要画面结构与卖点逻辑。

翻译要求：
{supplement}

质量要求：
1. 翻译语义准确，语气自然。
2. 字幕节奏和时间轴尽量稳定。
3. 结果需适配电商展示或跨境投放场景。
```

## 4. 与相邻功能的边界

### 4.1 与 `video-watermark` 的边界

- `video-translate`：核心是语言处理与字幕翻译
- `video-watermark`：核心是去除水印、字幕或角标

### 4.2 与 `video-clarify` 的边界

- `video-translate`：不以增强清晰度为核心目标
- `video-clarify`：不处理语言翻译

## 6. 当前版本结论

当前 `video-translate` 已落地的真实能力可以定义为：

+ 上传 1 条视频
+ 选择 3 种翻译模式之一
+ 选择目标语言
+ 填写翻译要求
+ 输出 1 条翻译处理结果视频

当前 `video-translate` 尚未落地的能力也应明确标注：

+ 当前页面未开放显式普通/高级模式切换
+ 当前不应被表述为视频配音重制或剧情重拍能力
