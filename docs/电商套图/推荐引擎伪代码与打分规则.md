# 推荐引擎伪代码与打分规则

> 用途：给后端 / 算法实现“套图类型推荐”时使用。  
> 输入依赖：`image_type_definitions.json`、`category_strategy_rules.json`、`platform_type_rules.json`、`platform_category_priorities.json`、`market_visual_rules.json`。其中 `market_visual_rules.json` 负责平台、市场、语言、卖点、视觉风格的独立值级提示词，以及可选组合增强。  
> 更新时间：2026-05-06

---

## 1. 目标

推荐引擎需要基于以下输入，为用户输出：

- `must_have`
- `recommended`
- `optional`
- `not_recommended`

并为每个可推荐类型补齐：

- 推荐理由
- Prompt
- Negative Prompt
- Layout Guidance
- Text Guidance
- 风险标签

## 3. 总体流程

```text
全量类型
-> 平台过滤
-> 品类过滤
-> 平台优先级打分
-> 品类优先级打分
-> 平台 / 市场 / 语言 / 卖点 / 风格偏好加权
-> 特殊规则修正
-> 分档输出
-> 生成推荐理由与最终 prompt
```

## 5. 伪代码

## 5.1 主流程伪代码

```text
function recommendImageTypes(input):
    allTypes = load(image_type_definitions)
    categoryRule = getCategoryRule(input.category_key)
    marketContext = getMarketContext(
        input.platform,
        input.market,
        input.language,
        input.selling_point,
        input.visual_style
    )

    candidates = []

    for typeDef in allTypes:
        candidate = initCandidate(typeDef)

        platformRule = getPlatformRule(input.platform, typeDef.type_key)

        if platformRule exists and platformRule.is_allowed == false:
            candidate.allowed = false
            candidate.blocked_reasons.append("blocked_by_platform")

        if categoryRule exists:
            if categoryRule.applicable_image_types not empty and typeDef.type_key not in applicable_image_types:
                candidate.allowed = false
                candidate.blocked_reasons.append("not_applicable_for_category")

            if typeDef.type_key in categoryRule.forbidden_image_types:
                candidate.allowed = false
                candidate.blocked_reasons.append("forbidden_by_category")

        if candidate.allowed == false:
            candidates.append(candidate)
            continue

        score = 0

        score += getPlatformBaseScore(platformRule)
        score += getCategoryRecommendedScore(categoryRule, typeDef.type_key)
        score += getPlatformCategoryPriorityScore(input.platform, input.category_key, typeDef.type_key)
        score += getMarketStyleBiasScore(marketContext, typeDef.type_key)
        score += getStructuredDataBonus(input.final_structured_data, typeDef.type_key)
        score += getPlatformCategorySemanticBonus(input, typeDef.type_key)

        riskFlags = detectRiskFlags(input, typeDef.type_key)
        score += getRiskPenalty(riskFlags)

        candidate.score = score
        candidate.risk_flags = riskFlags
        candidate.recommendation_reason = buildReasons(...)
        candidates.append(candidate)

    result = bucketize(candidates)
    result = attachPromptArtifacts(result, input, categoryRule, marketContext)
    return result
```

说明：

- `getMarketContext(...)` 不再返回单条 `market + language + visual_style` 组合行
- 而是分别读取 `platform`、`market`、`language`、`selling_point`、`visual_style` 五个独立字段 prompt
- 再额外匹配 `combination_rules`
- 输出形态建议为：

```json
{
  "value_prompts": {
    "platform": "",
    "market": "",
    "language": "",
    "selling_point": "",
    "visual_style": ""
  },
  "combination_prompts": [],
  "bias_image_types": []
}
```

## 5.2 平台基础分

```text
function getPlatformBaseScore(platformRule):
    if no platformRule:
        return 40
    return platformRule.priority
```

解释：

- 如果平台表里有该类型，就直接以平台优先级为基础分
- 如果平台没有显式配置，给一个保守默认值 `40`

---

## 5.3 品类推荐分

```text
function getCategoryRecommendedScore(categoryRule, typeKey):
    if no categoryRule:
        return 0

    score = 0

    if typeKey in categoryRule.recommended_image_types:
        score += 20

    if typeKey in categoryRule.extra_image_types:
        score += 10

    return score
```

---

## 5.4 平台 × 品类优先级分

```text
function getPlatformCategoryPriorityScore(platform, categoryKey, typeKey):
    row = find(platform_category_priorities, platform, categoryKey)
    if no row:
        return 0

    score = 0

    if typeKey in row.preferred_image_types:
        score += min(row.priority / 5, 20)

    return score
```

说明：

- `priority = 100` 时最高额外加 `20`
- 这个分数用于拉开平台 + 品类的明显偏好

---

## 5.5 平台 / 市场 / 语言 / 卖点 / 风格偏好分

```text
function getMarketStyleBiasScore(marketContext, typeKey):
    if no marketContext:
        return 0

    if typeKey in marketContext.bias_image_types:
        return 8

    return 0
```

说明：

- `bias_image_types` 来自命中的 `combination_rules`，或独立字段配置衍生出的轻量偏好
- 这层只做轻量偏置，不覆盖平台和品类主逻辑

## 5.6 结构化信息加分

```text
function getStructuredDataBonus(data, typeKey):
    score = 0

    if typeKey in ["detail_closeup", "detail_feature", "material_craft"] and data["视觉生成标签"]["display_focus"] not empty:
        score += 6

    if typeKey in ["scene_image", "lifestyle_image", "styling_scene"] and data["使用场景"]["usage_scenarios"] not empty:
        score += 6

    if typeKey in ["audience_match", "human_interaction", "try_on_or_demo"] and data["目标人群"]["target_audience"] not empty:
        score += 5

    if typeKey in ["specification_chart", "compatibility_info"] and data["参数与限制项"]["specifications"] not empty:
        score += 6

    if typeKey in ["core_selling_point", "advantage_summary"] and data["核心卖点"]["selling_points"] not empty:
        score += 6

    return score
```

## 5.7 语义加分

有些平台和品类虽然没明写在配置里，但语义上明显匹配，可做轻量修正。

```text
function getPlatformCategorySemanticBonus(input, typeKey):
    score = 0

    if input.platform in ["xiaohongshu", "douyin", "tiktok_shop"] and typeKey in ["short_video_cover", "scene_image", "lifestyle_image"]:
        score += 4

    if input.category_key == "fashion_apparel" and typeKey in ["fit_explanation", "styling_scene", "try_on_or_demo"]:
        score += 4

    if input.category_key in ["industrial_goods", "hardware_tools", "commercial_equipment"] and typeKey == "b2b_industrial_sheet":
        score += 6

    return score
```

## 5.8 风险识别

```text
function detectRiskFlags(input, typeKey):
    risks = []

    if input.platform == "amazon" and typeKey == "holiday_campaign":
        risks.push("conflict_with_platform")

    if input.category_key == "virtual_service" and typeKey in ["product_white_bg", "multi_angle", "detail_closeup"]:
        risks.push("conflict_with_product")

    if typeKey in ["specification_chart", "compatibility_info"] and final_structured_data["参数与限制项"]["specifications"] is empty:
        risks.push("insufficient_information")

    if typeKey in ["hero_banner", "lifestyle_image"] and input.visual_style == "conversion_direct" and input.platform in ["jd", "1688"]:
        risks.push("style_overreach")

    return risks
```

---

## 5.9 风险扣分

```text
function getRiskPenalty(riskFlags):
    penalty = 0

    for risk in riskFlags:
        if risk == "conflict_with_platform":
            penalty -= 60
        else if risk == "conflict_with_product":
            penalty -= 50
        else if risk == "insufficient_information":
            penalty -= 15
        else if risk == "style_overreach":
            penalty -= 10
        else if risk == "text_dependency":
            penalty -= 8

    return penalty
```

说明：

- 平台冲突和商品冲突需要强惩罚
- 信息不足不一定完全禁用，只是降低推荐级别

## 6. 分档规则

```text
function bucketize(candidates):
    must_have = []
    recommended = []
    optional = []
    not_recommended = []

    for candidate in candidates:
        if candidate.allowed == false:
            not_recommended.append(candidate)
            continue

        if candidate.score >= 95:
            must_have.append(candidate)
        else if candidate.score >= 80:
            recommended.append(candidate)
        else if candidate.score >= 60:
            optional.append(candidate)
        else:
            not_recommended.append(candidate)

    return {
        must_have,
        recommended,
        optional,
        not_recommended
    }
```

## 7. 推荐理由生成规则

每个候选项都需要生成可读的推荐理由，方便前端展示给用户。

### 7.1 规则模板

```text
如果该类型命中了平台优先：
  "适合 {platform} 平台的核心展示逻辑"

如果命中了品类推荐：
  "适合 {category_key} 品类表达 {某特征}"

如果命中了市场风格偏好：
  "符合 {market} 市场和 {visual_style} 风格的视觉偏好"

如果命中了结构化信息补强：
  "当前商品已具备足够的 {卖点/参数/场景/细节} 信息，适合生成此类型"
```

### 7.2 示例

`xiaohongshu + fashion_apparel + styling_scene`

推荐理由：

- 适合小红书电商的种草与穿搭表达语境
- 当前商品属于服饰鞋包，穿搭场景图能更直观体现版型和风格
- 当前视觉风格偏生活方式感，适合以场景化方式提升代入感

## 9. Goal / Use Case 生成建议

### 9.1 Goal 模板

- `product_white_bg`: 用于清晰展示商品主体，适合作为首图或基础展示图
- `core_selling_point`: 用于强化商品最重要的购买理由
- `scene_image`: 用于帮助用户理解商品在真实场景中的使用状态
- `specification_chart`: 用于快速传达尺寸、参数和关键规格
- `b2b_industrial_sheet`: 用于支撑理性采购和询盘决策

### 9.2 Use Case 模板

- `Amazon PDP 主图`
- `详情页卖点分屏`
- `短视频商品卡封面`
- `活动页 Banner`
- `B2B 产品详情参数页`

## 10. 推荐引擎最小实现建议

### P0

- 平台过滤
- 品类过滤
- 分数计算
- 分档输出
- 推荐理由

### P1

- 风险识别
- 市场 / 风格偏置
- 结构化信息加分

### P2

- 历史点击 / 使用行为加权
- 用户偏好学习
- 不同平台和类目的 AB Test 调优

---

## 11. 一句话实现原则

推荐引擎不要依赖大模型“从零想推荐”，而应先由规则和配置完成候选筛选与排序，再由模型只负责补充推荐理由和最终自然语言包装。
