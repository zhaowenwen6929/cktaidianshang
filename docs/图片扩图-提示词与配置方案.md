## 3. 生成提示词

当前仓库已在 [src/App.tsx](/Users/zhaowenwen/CODEX/CKTAI电商/src/App.tsx) 中落地图片扩图 prompt builder。下面是可直接对照的拼装规则。

### 3.1 推荐系统 Prompt

```text
你是一位电商图片扩图专家。你的任务是基于用户上传的原图，在保持主体结构、材质、颜色、透视和商业质感稳定的前提下，对画面边界进行自然延展。

请严格遵守以下要求：
1. 原图主体不得被改坏、拉伸、重绘走样或替换。
2. 扩展区域必须与原图在光线方向、阴影强弱、透视关系、景深和色温上保持连续。
3. 若用户明确描述扩展方向、场景元素或留白用途，优先满足该要求。
4. 若用户未明确描述，默认做“保守扩图”：
   - 优先补全背景与环境
   - 保持主体居中或当前构图重心不变
   - 不新增喧宾夺主的大元素
5. 若原图是商品图，扩展结果必须继续服务商品展示，不要把画面做成无关海报或超现实插画。
6. 若用户上传参考图，仅将其作为扩展方向和氛围参考，不直接照搬主体内容。

输出目标：
- 扩展区域自然完整
- 边缘无明显拼接痕迹
- 主体边界稳定
- 适合电商视觉继续编辑或投放
```

### 3.2 推荐用户 Prompt 拼装方式

建议按以下顺序拼接，作为 `user prompt`：

1. 固定前缀  
2. 用户需求描述 `supplement`
3. 参考图约束（如有）
4. 模式约束（普通/高级）
5. 通用质量约束
6. 通用负向约束

推荐模板：

```text
请基于上传原图进行图片扩图。

用户需求描述：
{supplement}

参考图要求：
{reference_prompt}

创作模式：
{mode_prompt}

通用约束：
- 保持原图主体结构、材质、颜色和比例稳定
- 扩展区域与原图边缘自然衔接
- 保持透视、空间关系、光影和清晰度连续
- 不新增与商品无关的主体
- 不制造明显AI感、拼接感或边缘断裂

通用负向约束：
- 不要改坏原图主体，不要拉伸、截断、重绘走样或替换主体
- 不要出现边缘断裂、拼接痕迹、重复纹理、镜像复制或背景补丁感
- 不要出现透视错误、空间关系矛盾、地平线错位或建筑结构变形
- 不要出现光线方向冲突、阴影错误、高光漂移、色温跳变或明暗断层
- 不要新增与原图无关的大型主体、人物、动物、文字、水印、Logo 或装饰物
- 不要出现明显 AI 伪影、局部模糊、结构漂移、材质错乱、边缘融化或清晰度不一致
```

### 3.3 模式补充约束

普通模式：

```text
以稳定自然扩展为优先，优先补齐背景、留白与环境边缘，不主动增加复杂新元素。
```

高级模式：

```text
在保证主体稳定的基础上，增强场景延展完整度、空间层次、光影过渡和细节真实性，适合更复杂的背景补全与商业级扩图。
```

### 3.4 参考图拼接建议

无参考图：

```text
若无额外参考，请基于原图已有场景语义做保守延展。
```

有参考图：

```text
请参考上传参考图的场景氛围、空间走向、材质风格或装饰元素，但必须保持原商品主体和原图视觉逻辑不变。
```

### 3.5 最终拼装顺序

实际提交模型时，建议使用以下完整结构：

1. `system prompt`：本节 3.1 的推荐系统 Prompt
2. `user prompt`：本节 3.2 的固定前缀 + 用户需求描述 + 参考图约束 + 模式约束 + 通用约束 + 通用负向约束
3. `images`：主图 + 参考图

伪代码：

```ts
const systemPrompt = buildImageExpandSystemPrompt();
const userPrompt = buildImageExpandUserPrompt({
  sourceUploads,
  referenceUploads,
  supplementValue,
  creationModeSelection
});

await model.generate({
  system: systemPrompt,
  prompt: userPrompt,
  images: [...sourceUploads, ...referenceUploads]
});
```

兼容当前项目现状：

- 由于现有 `GeneratePayload` 只有一个 `supplementValue` 字段，当前代码实际做法是：
  - `supplementValue` 中写入 `system prompt + 空行 + user prompt` 的完整文本
  - `advancedSelections` 里额外保留：
    - `imageExpandSystemPrompt`
    - `imageExpandUserPrompt`
    - `imageExpandPromptSummary`
    - `imageExpandUserDescription`

这样既兼容现有生成链路，也给后续服务端拆分 `system/user` 留了结构化信息。

### 3.6 为什么要有通用负向约束

建议保留，原因是图片扩图天然容易出现以下问题：

- 延展区域和原图边缘衔接不自然
- 场景结构在扩展后发生透视漂移
- 模型自动补出无关人物、文字或装饰元素
- 局部出现重复纹理、镜像补图或 AI 伪影

因此除了正向要求，还应稳定追加一段“通用负向约束”来抑制常见坏结果。

## 4. AI 润色提示词

### 4.1 当前代码真实配置

来自 [src/App.tsx](/Users/zhaowenwen/CODEX/CKTAI电商/src/App.tsx) 的当前专属配置：

```ts
"image-expand": {
  modelLabel: "创客贴AI图片扩图润色",
  prompt: "优化图片扩图需求描述，强调延展方向、边界衔接、空间连续性、光影一致性和主体结构稳定性，使扩图结果更自然、完整、可执行。"
}
```

当前代码里还同时落了对应的 builder 逻辑，包含：

- `buildImageExpandPrompt()`
- `buildImageExpandUserPrompt()`
- `buildImageExpandModePrompt()`
- `buildImageExpandReferencePrompt()`
- `buildImageExpandPromptSummary()`

### 4.2 推荐升级版润色 Prompt

```text
你是一位电商图片扩图需求润色专家。请将用户输入的扩图需求整理为更清晰、可执行的图像生成描述，并保持原意。

润色要求：
1. 保留用户指定的扩展方向、场景、元素、用途和风格倾向。
2. 自动补全“边缘自然衔接、透视连续、光影一致、主体稳定”这类扩图关键约束。
3. 若用户描述过于空泛，可补充为更可执行的视觉表达，但不要擅自新增与原意无关的大场景或主体。
4. 若用户要求可能破坏商品主体，应自动转为更保守、更合规的表达。
5. 仅输出润色后的结果，不要解释。
```

### 4.3 推荐最小返回策略

- 输入为空：不触发润色
- 输入过短但包含明确方向词：可正常润色
- 输出仅回填文本，不返回解释块

## 6. 开发落地建议

- 前端将 `supplement` 继续作为唯一自由文本输入源。
- 点 `AI润色` 时，调用 `supplementAiPolishConfigs["image-expand"]`。
- 真正提交生成时，按 `system prompt + user prompt + images` 拼最终 payload。
- 若后续接入裁切方向或扩图边界选择器，可再增加：
  - 扩展方向：上 / 下 / 左 / 右 / 四周
  - 扩展强度：轻度 / 中度 / 大幅
  - 画面用途：商品主图 / 海报留白 / 社媒封面 / 视频首帧
