## 使用流程
1. 上传商品图（`upload-main`）
2. 选择创作模式（`creation-mode`：普通/高级/中文增强）
3. 配置高级设置（`advanced-settings`）
4. 填写补充说明（`supplement`，可选）
5. 上传参考图（`upload-reference`，可选）
6. 生成

## 端到端使用流程
1. 用户上传商品图（`upload-main`，最多24张）。
2. 系统执行图片理解与商品信息提取，识别商品品类、产品类型和最适合放大的细节方向。
3. 系统触发 AI Assist，回填细节图高级字段。
4. 用户手动修正高级字段，并可上传 1 张参考图控制局部焦点、材质质感或镜头风格。
5. 用户选择创作模式参数（`modeId` / `ratio` / `resolution` / `count`）。
6. 用户填写补充说明（可选，可走 AI 润色）。
7. 若业务链路上已有平台信息，则在最终提示词拼接阶段注入 `platformLabel` 对应平台规则。
8. 系统按 strict 规则组装最终提示词并提交生成。

## 1.1 细节图特殊模块（创作模式与计费口径）
细节图复用 `spoke` 创作模式配置，但需求文档里必须写清楚，否则开发容易误按普通附图能力处理。

```json
{
  "creationModeConfig": {
    "modeId": ["normal", "advanced", "cn-enhanced"],
    "ratio": ["自适应尺寸", "1:1", "3:4", "4:5", "9:16", "2:3", "16:9", "4:3", "5:4", "3:2", "21:9"],
    "count": [1, 2],
    "resolution": {
      "normal": [],
      "cn-enhanced": [],
      "advanced": ["1K", "2K", "4K"]
    }
  },
  "creditRule": {
    "normal": 5,
    "cn-enhanced": 10,
    "advanced": {
      "1K": 10,
      "2K": 15,
      "4K": 20
    },
    "formula": "generateCost = 主图上传数量 × 出图数量 × 当前模式单张积分"
  }
}
```

实现要求：

+ 参考图（`upload-reference`）只参与风格参考，不参与计费倍乘。
+ `resolution` 仅在 `advanced` 模式下展示和传值，其他模式应为空或不传。
+ 细节图多张生成时，应保持同一商品的细节表达口径和视觉风格一致。

这些字段不是都来自同一个面板，开发实现时要区分“页面字段”和“链路注入字段”。

```json

    "platformLabel": "外层业务链路注入，不在高级设置面板内",
    "productCategory": "图片识别链路或商品中心识别结果",
    "productType": "高级设置字段，可人工改写",
    "displayType": "高级设置字段，可人工改写",
    "supplement": "用户自由输入，可为空"
  },
  "fallback": {
    "platformLabel": "全平台通用（16平台）",
    "productCategory": "通用品类",
    "productType": "智能识别",
    "displayType": "单细节展示"
  }
}
```

实现要求：

+ `platformLabel` 缺失时，不阻塞生成，默认命中 `全平台通用（16平台）` 规则。
+ `productCategory` 与 `productType` 冲突时，优先按 `productType -> category` 映射结果修正，并将该字段加入 `needsUserConfirm`。
+ `displayType` 是局部展示策略，不是细节内容本身；真实要放大的局部区域仍需由图片识别、补充说明或后续 builder 推导。

## 2.1 `ruleLevel` 多规则使用逻辑（同一平台存在多条规则时）
适用场景：一个平台可能同时命中“平台基础规则 + 渠道规则 + 图位规则 + 风控规则”。

### 2.1.1 规则定位
+ `ruleLevel=A`：高优先级硬约束，不可被低级规则覆盖。
+ `ruleLevel=B`：常规约束，可被 A 覆盖。
+ `ruleLevel=C`：补充约束，可被 A/B 覆盖，且可在 token 紧张时优先裁剪。

### 2.1.2 组装顺序（强制）
1. 合并所有命中规则的 `required`（去重后全部保留）。
2. 合并所有命中规则的 `forbidden`（去重后全部保留）。
3. `prompt` 按优先级拼接：`A -> B -> C`。
4. 若提示词长度超限，仅从低优先级描述裁剪：先裁 `C.prompt`，再裁 `B.prompt`；`A.prompt`、`required`、`forbidden` 不裁。

### 2.1.3 冲突处理（强制）
+ 若高低级规则存在冲突，按优先级覆盖：`A > B > C`。
+ 对细节图功能，若平台规则与“细节强放大”冲突，优先保平台硬规则，并把结果限制在“附图/详情图/补充图”语义内。

## 拼装规则
### 拼装顺序
1. `taskGoal`（任务目标）
2. `categoryRule`（品类规则）
3. `platformRule`（平台规则）
4. `categoryDimensionDirectionRule`（细节维度与展示方向规则）
5. `parameterBlock`（参数块）
6. `valuePromptBlock`（字段值扩展约束）
7. `requiredBlock`（必须满足）
8. `forbiddenBlock`（禁止事项）
9. `universalNegative`（通用负向约束）
10. `universalQuality`（通用质量要求）
11. `supplement`（用户补充要求）
12. `referenceImageBlock`（参考图约束）

组装要求：

+ `requiredBlock / forbiddenBlock / universalNegative / universalQuality` 属于不可裁剪段。
+ token 超限时，优先裁剪 `valuePromptBlock -> platformRule -> supplement`，不要先裁硬约束。
+ 若后续接入 `detailDimension / detailDirection / platformInfo` 这类中间字段，应继续归入 `categoryDimensionDirectionRule` 与 `valuePromptBlock`，不要另起一套模板。

## 三个关键能力的提示词配置
### 图片识别获取信息
用途：

+ 识别细节图生成所需的品类、产品类型和细节展示方式；
+ 输出结构化 JSON，供字段回填和后续提示词组装使用；
+ 判断适合放大的局部区域、材质类型和结构重点，而不是只做泛化商品识别。

提示词：

```json
你是一位电商商品细节图理解专家。请根据输入商品图，提取“细节图生成”所需信息，并严格输出 JSON。

任务要求：
1) 识别商品所属品类（用于 productCategory）。
2) 基于图像线索，预测细节图字段推荐值：productType, displayType。
3) 识别最适合放大的局部区域、材质线索和结构重点，供后续 prompt builder 使用。
4) 所有推荐值必须从给定 options 中选择；若无法判断，返回空字符串或最保守值。
5) 不输出解释文字，不输出 Markdown，仅输出 JSON。

输出 JSON Schema：
{

    "categoryId": "string",
    "categoryLabel": "服饰类|鞋靴类|箱包类|珠宝饰品类|美妆个护类|食品饮料类|家居百货类|家电数码类|家具大件类|母婴玩具类|宠物用品类|汽配五金类|通用品类",
```

### AI帮写
用途：

+ 在用户点击“AI帮写”时，回填细节图高级设置字段；
+ 仅输出字段键值，不输出额外解释；
+ 优先给出“有助于真实细节放大”的安全值，而不是无依据的复杂拼接方案。

提示词：

```json
你是一位商品细节图策划师。请根据商品图片，回填 goods-detail 的高级设置字段。

必须遵守：
1) 仅返回以下字段：productType, displayType。
2) 能确认的字段必须从提供的 options 中选取一个值。
3) 无法确认的字段不要编造，不要猜测，直接留空字符串 ""，并把字段名加入 needsUserConfirm。
4) productType 回填后，必须基于 productTypeToCategoryMap 推导并回填 productCategory；若冲突按映射结果覆盖并标记 needsUserConfirm。
5) 若无法判断更复杂的展示形式，displayType 优先回填“单细节展示”而不是激进拼接方案。
6) 只输出 JSON，不要输出解释。

输出格式：
{
  "fieldValues": {
    "productCategory": "string",
    "productType": "string",
    "displayType": "string"
  },
  "needsUserConfirm": ["fieldKey1", "fieldKey2"]
}
```

回填策略：

+ `productType` 可以识别、`displayType` 无把握时，只回填 `productType`，`displayType` 留空或回填 `单细节展示`。
+ `productType` 未命中映射表时，`productCategory=通用品类`，并将 `productType / productCategory` 加入 `needsUserConfirm`。
+ 当前前端默认不展示 `AI帮写` 入口，但服务端或后续版本接入时，可直接复用本段协议。

### 文本润色
用途：

+ 对用户补充说明进行语义增强；
+ 生成可执行、约束清晰、适合细节图模型的补充文本；
+ 自动过滤“质感高级一点”“微距一点”等弱约束表达，转成明确的局部和结构要求。

提示词：

```json
你是一位电商细节图文案润色专家。请将下方用户的补充说明优化为“可执行的图像生成约束”，并保持原意。

补充说明：
xxxxxxxxxxxx

润色目标：
1) 强化局部焦点、放大区域、材质纹理、工艺位置和结构真实性。
2) 明确是单细节还是多细节，是否需要功能关联、材质对比或使用痕迹。
3) 避免空泛词，改成可执行描述（局部区域、材质、边缘、结构、镜头距离、不能出现的错误）。
4) 若用户写了可能违规、误导或不真实的要求，自动转为合规表述，不要原样保留。
5) 输出一段最终可直接拼进提示词的文本。

输出要求：
- 仅输出润色后的文本，不要解释。
- 60~180字为宜。
- 不得包含夸张功效、虚构结构、伪剖面、违规Logo/水印或误导性表达。
```

默认润色方向：

+ 对 `goods-detail` 来说，重点不应该是“商业说服力”或“标题层级”，而应该是“局部焦点、工艺区域、材质纹理、边缘净度、结构真实性”。
+ 若用户未明确写放大区域，润色时优先补成“聚焦一个最关键细节区域，避免多焦点干扰”这类保守表达。

## 结论
一键细节图真正可开发落地的关键不是“做一张放大图”，而是让平台、品类、展示形式和局部真实感同时成立。
