# AI商品图-模特调整-提示词与配置方案

## 1. 功能目标

“模特调整”用于围绕单张模特图执行定向人物编辑，当前支持以下 6 类能力：

1. `AI换模特`
2. `模特换表情`
3. `模特多角度`
4. `模特多姿势`
5. `模特发型`
6. `模特微调`

该能力面向服饰电商、穿搭展示、人物场景化商品图等场景，要求在尽量保留原图服装、商品关系、构图与商业质感的前提下，对人物局部或整体做可控编辑。

## 2. 配置目标

本方案将提示词拆为两层：

1. `操作级 prompt`
作用：定义当前编辑模式的总目标、保留约束和常见负向约束。

2. `选项级 optionPrompts`
作用：当某个操作下存在固定选项时，为每个选项补充更具体的方向性提示词。

最终可用于：

1. 前端侧展示和调试
2. 提示词拼接时作为结构化输入
3. 后续接 AI 润色、中文增强模型和埋点分析

## 4. 操作级提示词

### 4.1 AI换模特

```text
在保留原图服装、商品、构图、光线和主体展示逻辑的前提下，替换为新的真人模特。新模特需与服饰穿着关系自然，肢体结构合理，保持电商成片质感，避免多余人物、畸形手脚、服装变形和面部失真。
```

说明：

1. 本模式没有固定下拉选项，依赖“需求描述”自由输入补充。
2. 上传参考图时，可优先参考参考图中的脸型、气质、姿态或人物风格，但仍需服从原图服装展示逻辑。

### 4.2 模特换表情

```text
仅调整模特面部表情，保持人物身份、发型、服装、姿势、镜头角度和背景基本不变。要求五官结构自然，嘴部与眼神协调，避免夸张变形、面部崩坏和年龄气质漂移。
```

### 4.3 模特多角度

```text
调整模特拍摄视角，保持人物身份、服装款式、面料、颜色和场景氛围一致。新角度应符合真实摄影透视，身体结构完整，避免服装版型变化、四肢错位和视角跳变。
```

### 4.4 模特多姿势

```text
调整模特姿势，保持同一人物、服装、场景和镜头风格一致。动作需符合人体结构与重心逻辑，兼顾服装展示效果，避免关节扭曲、肢体穿插、服装拉坏和姿态僵硬。
```

### 4.5 模特发型

```text
调整模特发型，保持人物身份、脸型、妆面、服装和画面风格一致。发型变化应真实自然，发际线、发量、走向和光泽合理，避免头部比例异常、发丝穿帮和风格突兀。
```

### 4.6 模特微调

```text
在不改变模特主体身份和服装核心展示效果的前提下进行局部微调。修改范围应精确可控，保持皮肤、五官、配饰和整体气质自然统一，避免过度修饰、风格漂移和局部违和。
```

## 6. 推荐提示词拼接规则

建议按以下顺序拼接：

1. 功能基础前缀
2. 操作级 `prompt`
3. 选项值文本
4. 选项级 `optionPrompt`
5. 用户自由输入补充描述
6. 参考图约束
7. 通用负向约束

推荐伪代码：

```ts
const finalPromptParts = [
  "请基于上传的模特图进行人物编辑。",
  selectedEditMode.prompt,
  selectedOption ? `用户选择：${selectedOption}` : "",
  selectedOptionPrompt ?? "",
  freeTextSupplement ?? "",
  hasReference ? "如上传参考图，请优先参考参考图中的人物风格、脸型、气质或局部特征。" : "",
  "保持服装、商品关系、人物结构、光影与商业成片质感自然统一。"
].filter(Boolean);

const finalPrompt = finalPromptParts.join(" ");
```

### 6.1 通用负向约束

“通用负向约束”指无论用户选择哪一种“模特调整”操作，都建议在最终提示词末尾追加的一组稳定约束，用于减少模型误生、结构错误和偏题生成。

推荐统一文案：

```text
禁止生成多余人物、第二张脸、第二双手或多余肢体；禁止出现手脚畸形、关节扭曲、五官错位、眼睛嘴巴不对称、面部崩坏；禁止改变原服装的款式、版型、长度、颜色、材质纹理和商品主体关系；禁止引入与当前编辑目标无关的大幅场景变化、镜头跳变和风格漂移；禁止出现低清晰度、过度磨皮、过度美颜、局部穿帮、边缘残缺、发丝断裂、配饰结构错误和文字水印伪影。最终画面必须保持单人主体、结构真实、光影统一、服装展示清晰、商业成片自然。
```

建议作用：

1. 稳定单人主体，避免多人物误生。
2. 约束人物结构，减少脸崩、手崩、肢体错误。
3. 约束服装和商品关系，避免编辑人物时把衣服一并改坏。
4. 约束风格漂移，避免用户只想微调却被模型改成重构。
5. 提升电商可用性，减少脏边、伪影、低清问题。

## 9. 用户输入异常处理

### 9.1 问题定义

用户自由输入的补充说明，可能并不总是围绕当前“模特调整”操作本身，常见情况包括：

1. 输入了与当前操作无关的要求。
2. 输入了会覆盖当前操作目标的冲突要求。
3. 输入了另一个功能域的需求，例如改背景、加文案、换商品、生成海报。
4. 输入内容过于泛化、情绪化或不可执行。

### 9.2 处理原则

建议遵循以下规则：

1. 以当前已选功能和当前操作类型为最高优先级。
2. 用户补充说明只作为“当前操作的补充”，不应推翻当前操作本身。
3. 与当前操作强相关的内容保留并参与拼接。
4. 弱相关但可兼容的内容，降级为风格性补充。
5. 完全无关或跨功能内容，不直接拼入最终主提示词。
6. 明显冲突的内容，优先保留当前操作目标，并提示用户调整输入。

### 9.3 建议分类

可将用户输入分成三类：

1. 强相关
示例：在“模特换表情”里输入“笑得自然一点，不要露齿太多”。
处理：直接拼接。

2. 弱相关但可兼容
示例：在“模特发型”里输入“整体更有韩系清新感”。
处理：保留，但放在补充描述尾部，作为风格辅助，不覆盖主编辑目标。

3. 不相关或跨功能
示例：在“模特换表情”里输入“背景换成海边，再加一行促销文案”。
处理：不直接进入主提示词；可忽略、截断，或提示用户切换到对应功能。

### 9.4 推荐处理策略

#### 策略 A：前端静默过滤

适用：先追求流程顺滑。

规则：

1. 提取与当前操作相关的片段进入 prompt。
2. 与当前操作明显无关的片段丢弃。
3. 不报错，直接按相关内容生成。

优点：

1. 用户操作成本低。
2. 不打断创作流程。

风险：

1. 用户可能误以为无关要求也会生效。

#### 策略 B：前端提示后再生成

适用：需要更强可解释性。

规则：

1. 若识别到大量无关内容，给出提示。
2. 提示用户“当前功能只处理人物调整，背景/文案/商品替换等需求不会生效”。
3. 用户确认后继续生成。

推荐提示文案：

```text
当前输入中包含与“模特调整”无关的需求，系统将仅保留与当前操作相关的内容进行生成；背景、文案、商品替换等要求不会在本次任务中生效。
```

#### 策略 C：AI润色阶段先做相关性清洗

适用：后续接大模型做补充说明润色时。

建议在润色 prompt 中增加一条约束：

```text
仅保留与当前操作直接相关的补充信息；如用户输入包含背景替换、文案生成、商品修改、版式设计等无关要求，请不要写入最终润色结果。
```

### 9.5 推荐默认方案

建议默认采用“静默过滤 + 轻提示”组合：

1. 系统内部只拼接与当前操作相关的内容。
2. 若检测到明显跨功能内容，在 UI 上给轻提示。
3. 不让无关内容进入最终 prompt。
4. 不让无关内容污染 AI 润色结果。

### 9.6 示例

示例 1：

- 当前操作：`模特多角度`
- 用户输入：`改成背面视角，同时把背景换成咖啡馆，再加秋季上新文案`

建议处理：

1. 保留：`改成背面视角`
2. 丢弃或提示无效：`背景换成咖啡馆`
3. 丢弃或提示无效：`加秋季上新文案`

示例 2：

- 当前操作：`模特微调`
- 用户输入：`戴细框眼镜，气质更知性，画面更高级一点`

建议处理：

1. `戴细框眼镜` 视为强相关，直接保留。
2. `气质更知性，画面更高级一点` 视为弱相关风格补充，可保留。

示例 3：

- 当前操作：`模特换表情`
- 用户输入：`衣服换成红色连衣裙`

建议处理：

1. 该输入与“换表情”冲突，不能直接拼入。
2. 应忽略该要求，或提示用户改用“AI换模特/换装类功能”。

## 10. 交互与实现约束

1. `AI换模特` 当前只有自由输入，不需要 `optionPrompts`。
2. 其他 5 个模式，固定选项命中后应自动带出对应 `optionPrompt`。
3. 若用户手动输入自定义值，则不强依赖固定选项映射，只拼接操作级 `prompt + 用户输入描述`。
4. 后续若接入“AI润色补充说明”，建议对用户自由输入部分进行润色，不改写操作级和选项级结构化提示词。
5. 若检测到与当前操作无关或冲突的用户输入，默认不应直接拼入最终 prompt，需先过滤、降级或提示。
6. 若未来增加更多微调能力，如“瘦脸”“换妆容”“加耳饰”，优先继续沿用 `optionPrompts` 扩展，不新增平行结构。
