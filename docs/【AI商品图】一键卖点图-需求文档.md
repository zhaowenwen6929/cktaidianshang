## 使用流程
1. 上传商品图（`upload-main`）
2. 选择创作模式（`creation-mode`：普通/高级/中文增强）
3. 配置高级设置（`advanced-settings`）
4. 填写补充说明（`supplement`，可选）
5. 上传参考图（`upload-reference`，可选）
6. 生成

## 端到端使用流程
1. 用户上传商品图（`upload-main`，最多24张）。
2. 系统执行图片理解与商品信息提取，识别商品品类、产品细分、适合的平台语境和卖点表达方向。
3. 系统触发 AI Assist，回填卖点图高级字段。
4. 用户手动修正高级字段，并可上传 1 张参考图控制视觉风格、版式或信息气质。
5. 用户选择创作模式参数（`modeId` / `ratio` / `resolution` / `count`）。
6. 用户填写补充说明（可选，可走 AI 润色）。
7. 若业务链路上已有平台信息，则在最终提示词拼接阶段注入 `platformLabel` 对应平台规则。
8. 系统按 strict 规则组装最终提示词并提交生成。
9. 结果返回后，用户可继续换平台、换卖点结构、换目标市场做二次生成。

## 1.1 卖点图特殊模块（创作模式与计费口径）
卖点图复用 `spoke` 创作模式配置，但在需求文档中需要单独写清，避免开发误按场景图或白底图口径实现。

```json
{
  "creationModeConfig": {
    "modeId": ["normal", "advanced", "cn-enhanced"],
    "ratio": ["自适应尺寸", "1:1", "3:4", "4:5", "9:16", "2:3", "16:9", "4:3", "5:4", "3:2", "21:9"],
    "count": [1, 2],
    "resolution": {
      "normal": [],
      "cn-enhanced": [],
      "advanced": ["1K", "2K", "4K"]
    }
  },
  "creditRule": {
    "normal": 5,
    "cn-enhanced": 10,
    "advanced": {
      "1K": 10,
      "2K": 15,
      "4K": 20
    },
    "formula": "generateCost = 主图上传数量 × 出图数量 × 当前模式单张积分"
  }
}
```

实现要求：

+ 参考图（`upload-reference`）只参与风格参考，不参与计费倍乘。
+ `resolution` 仅在 `advanced` 模式下展示和传值，其他模式应为空或不传。
+ 最终 builder 使用 `modeId / ratio / resolution / count` 时，必须与计费口径保持一致，避免“前端展示模式”和“后端拼装模式”不一致。

## 1.2 平台、品类与默认值约定
这些字段不是都来自同一个表单模块，开发实现时要区分“用户显式填写”和“链路注入”。

```json
{
  "fieldSource": {
    "platformLabel": "外层业务链路注入，不在高级设置面板内",
    "productCategory": "图片识别链路或商品中心识别结果",
    "productType": "高级设置字段，可人工改写",
    "supplement": "用户自由输入，可为空"
  },
  "fallback": {
    "platformLabel": "全平台通用（16平台）",
    "productCategory": "通用品类",
    "productType": "智能识别",
    "sceneType": "智能匹配",
    "copyLanguage": "无文案",
    "presentationForm": "智能匹配"
  }
}
```

实现要求：

+ `platformLabel` 缺失时，不阻塞生成，默认命中 `全平台通用（16平台）` 规则。
+ `productCategory` 与 `productType` 冲突时，优先按 `productType -> category` 映射结果修正，并将该字段加入 `needsUserConfirm`。
+ `mainTitle`、`subtitle` 属于文案结构开关，不等于用户直接输入标题文案；若后续接入显式文案输入框，应作为新字段扩展，不应复用这两个开关值。

## 2. 平台提示词配置
说明：

+ 卖点图允许标题、数据、图标、线条、强调框等信息承载，不等于白底主图，也不等于买家秀真实拍摄图。
+ 平台规则应转成“允许承载多少信息、如何保证主体清晰、哪些表达不能出现”的卖点图专属规则。
+ `ruleLevel` 含义：
  - `A`: 官方明确或高一致性强约束
  - `B`: 官方间接+行业稳定约束
  - `C`: 公开趋势明确，但仍建议后台复核

## 2.1 `ruleLevel` 多规则使用逻辑（同一平台存在多条规则时）
适用场景：一个平台可能同时命中多条规则（基础规则、活动规则、渠道规则、风控规则）。

### 2.1.1 规则定位
+ `ruleLevel=A`：高优先级硬约束（官方明确或高一致性约束），不可被低级规则覆盖。
+ `ruleLevel=B`：常规约束（官方间接+行业稳定约束），可被 A 覆盖。
+ `ruleLevel=C`：补充约束（待复核或策略性补充），可被 A/B 覆盖，且可在 token 紧张时优先裁剪。

### 2.1.2 组装顺序（强制）
1. 合并所有命中规则的 `required`（去重后全部保留）。
2. 合并所有命中规则的 `forbidden`（去重后全部保留）。
3. `prompt` 按优先级拼接：`A -> B -> C`。
4. 若提示词长度超限，仅从低优先级描述裁剪：先裁 `C.prompt`，再裁 `B.prompt`；`A.prompt`、`required`、`forbidden` 不裁。

### 2.1.3 冲突处理（强制）
+ 若高低级规则存在冲突，按优先级覆盖：`A > B > C`。
+ 冲突判定建议以“语义键”维度进行（例如 `主体完整`、`文案密度`、`功效表述`、`比例兼容`），同语义仅保留最高等级版本。

### 2.1.4 最终拼接建议
```latex
平台硬性要求（A层）：{A层prompt合并}
平台常规要求（B层）：{B层prompt合并}
平台补充要求（C层）：{C层prompt合并，可裁剪}
平台必须满足：{required合并}
平台禁止事项：{forbidden合并}
```

## 4. 高级选项值扩展提示词配置
说明：

+ 卖点图不是“值文本直拼”功能，多个字段必须扩展成可执行约束。
+ 核心字段：`sceneType / coreSellingPoint / presentationForm / sellingPointFocus / mainTitle / subtitle / fontStyle / assistElement / copyLanguage / targetMarket`
+ 其中 `mainTitle`、`subtitle` 即使是“自动生成”，也必须扩成对文案职责和层级的要求。

开发要求：

+ 最终拼装优先使用 `docs/一键卖点图/AI商品图-一键卖点图-option_value_expansions.json` 中的 `valuePrompt`，不要只把字段值原样拼进 prompt。
+ 若某字段存在值但没有命中 `valuePrompt`，可保留在参数行中，但不应凭空生成一段新的扩展文案。
+ `mainTitle`（主标题）、`subtitle`（副标题）的扩展语义必须落在“标题数量、职责、层级、是否自动生成”上，不能写成泛化审美词。
+ `assistElement`（元素辅助）只能增强阅读路径和信息理解，不能变成覆盖主体的大面积设计元素。

## 拼装规则
### 拼装顺序
1. `taskGoal`（任务目标，来自 `mode_rules`）
2. `categoryRule`（品类约束，来自 `category_dimension_direction_rules`）
3. `platformRulePrompt`（平台约束，来自平台规则）
4. `sceneSlotAdvice`（图位用途限制，若平台或业务链路有图位说明则必须拼入）
5. `dimensionRule`（场景维度约束，来自 `sceneType`）
6. `directionRule`（卖点方向约束，来自 `sellingPointFocus`）
7. `parameterLine`（高级设置参数行）
8. `optionValuePrompts`（选项扩展约束）
9. `requiredRule`（必须满足）
10. `forbiddenRule`（禁止事项）
11. `universalNegative`（通用负向约束）
12. `universalQuality`（通用质量要求）
13. `supplement`（补充要求，可选）

组装要求：

+ `requiredRule / forbiddenRule / universalNegative / universalQuality` 属于不可裁剪段。
+ token 超限时，仅允许按 `optionValuePrompts -> directionRule -> dimensionRule -> categoryRule -> platformRulePrompt` 顺序裁剪。
+ `resolution` 为空时直接省略该字段，不输出 `分辨率=` 空值占位。

## 三个关键能力的提示词配置
### 图片识别获取信息
用途：

+ 识别品类与卖点图相关字段线索；
+ 输出结构化 JSON，供字段回填和后续提示词组装使用；
+ 判断适合的卖点表达方向，而不是泛化描述商品。

提示词：


### 文本润色
用途：

+ 对用户补充说明进行语义增强；
+ 生成可执行、约束清晰、适合卖点图模型的补充文本；
+ 自动过滤“好看一点”“高级一些”等弱约束表达。

提示词：

```json
你是一位电商卖点图文案润色专家。请将下方用户的补充说明优化为“可执行的图像生成约束”，并保持原意。

补充说明：
xxxxxxxxxxxx

润色目标：
1) 强化核心卖点、主副标题层级、信息阅读顺序和主体展示重点。
2) 明确标题数量、信息多少、文案位置和主体遮挡边界。
3) 避免空泛词，改成可执行描述（主体、标题、图标、数据、背景、限制）。
4) 若用户写了可能违规或误导的要求，自动转为合规表述，不要原样保留。
5) 输出一段最终可直接拼进提示词的文本。

输出要求：
- 仅输出润色后的文本，不要解释。
- 80~220字为宜。
- 不得包含违规词、夸张功效、虚假参数或误导性承诺。
```

## 结论
一键卖点图要真正可用，不能只做“商品+几句文案”的泛化提示词，至少要同时接入四层配置：

1. 真实代码字段层：页面已经有哪些字段、哪些值、哪些 AI 回填逻辑。
2. 平台规则层：把平台商品图要求转成“卖点图可承载多少信息、禁止什么表达”。
3. 品类规则层：不同品类决定卖点图更应强调什么信息、哪些细节不能被遮挡。
4. 选项值扩展层：每个高级选项值都要扩写为可执行的画面约束，不要只传值字符串。

这样生成的卖点图，才更接近“合规、正确、可投放、可转化”的真实业务需求。
