# 【视频创作】产品视频-需求文档

## 需求目标
用户输入：

1. 上传 1~5 张同一商品多视角图片
2. 选择创作模式与参数（普通/高级、时长、比例、分辨率、声音）
3. 输入完整视频脚本，或通过 AI 生成脚本参数后回填脚本
4. 可选开启旁白，补充旁白语言、音色和文案

系统输出：

+ 基于用户上传的多视角商品图，生成 1 条商品产品视频
+ 输出结果需围绕商品核心卖点组织镜头，并保持商品结构、材质、颜色和细节跨镜头稳定
+ 当用户开启旁白时，输出结果需带有与脚本一致的旁白表达方向

## 核心逻辑
产品视频不是“参考视频复刻”能力，也不是“原视频商品替换”能力。最终提示词必须由系统拼装，不直接照搬用户原始文本。执行链路如下：

1. 商品图理解：识别同一商品的多视角信息、结构特征、材质表现和适合强化的卖点
2. 视频参数注入：注入创作模式、时长、比例、分辨率、声音策略
3. 脚本信息融合：融合用户手写脚本，或融合 AI 生成脚本参数与补充说明
4. 旁白策略拼装：当旁白开启时，拼入语言、音色、旁白文案约束
5. 一致性约束：强制保持商品主体真实一致，不得跨镜头改款、改色、改结构

## 使用流程
1. 上传商品图（`upload-main`）
2. 选择卖点信息（`set-pack-selling-points`）
3. 选择市场与生成参数（`set-pack-strategy`）
4. 选择视频类型与声音策略（`video-replica-setup`）
5. 填写或生成视频脚本（`video-main-script-setup`）
6. 可选开启旁白，并补充旁白语言、音色、旁白文案
7. 生成

## 端到端使用流程
1. 用户上传 1~5 张同一商品多视角图片，作为整条视频唯一的商品主体依据。
2. 系统基于商品图做基础理解，识别商品主体、视角差异和关键卖点线索。
3. 用户在卖点区补充商品卖点信息，在市场配置区选择目标平台、目标市场、文案语种，并选择视频比例、时长、分辨率。
4. 用户在视频参数区选择顶部模式切换、爆款类型和声音策略。
5. 用户直接填写完整脚本，或点击 `AI生成` 打开脚本抽屉，填写脚本参数后生成脚本文案。
6. 如果用户开启旁白，继续补充旁白语言、音色和旁白文案；也可通过 `AI帮写` 生成旁白文案。
7. 系统将商品图理解结果、卖点信息、市场信息、视频参数、脚本内容、旁白策略一起组装为最终 prompt。
8. 系统提交生成任务，返回 1 条产品视频结果。

## 功能基础说明

### 1.1 功能定位

- 功能名称：`产品视频`
- 工具 Key：`video-main`
- 所属一级分组：`视频创作`
- 能力定位：基于同一商品多视角图片，生成单条产品展示/卖点讲解类视频

### 1.2 当前真实页面结构

- `creationModeConfigKey`：`video-main`
- `sectionOrder`：`["upload-main", "set-pack-selling-points", "set-pack-strategy", "video-replica-setup", "video-main-script-setup"]`
- 上传区：
  - 商品图：最多 `5` 张，必填
- 当前页面不上传参考视频
- 当前页面不单独展示传统 `supplement` 区，脚本区本身承担补充说明能力

补充说明：

+ `set-pack-selling-points` 在 `video-main` 中承担“商品卖点补充/提炼”输入角色
+ `set-pack-strategy` 在 `video-main` 中承担“目标平台、目标市场、文案语种、视频比例、时长、分辨率”配置角色
+ `video-replica-setup` 在 `video-main` 中承担“视频类型切换、爆款类型选择、声音策略”角色，属于复用区块，不应再按“参考视频复刻”语义理解

### 1.3 上传约束

```json
{
  "toolKey": "video-main",
  "uploads": {
    "main": {
      "label": "上传商品图",
      "required": true,
      "maxCount": 5,
      "hintTemplate": "最多5张，请上传同一产品多视角图片"
    }
  }
}
```

实现要求：

+ 上传图片必须为同一商品，不允许混入不同 SKU、不同颜色体系或不同结构版本
+ 多视角图优先覆盖正面、侧面、背面、局部细节等信息，供视频跨镜头调用
+ 若只上传 1 张图，系统仍可生成，但商品一致性和镜头丰富度会弱于多视角输入

## 2. 视频基础参数

产品视频当前由两个复用区块共同承载基础参数：

+ `set-pack-strategy`：承载目标平台、目标市场、文案语种、比例、时长、分辨率
+ `video-replica-setup`：承载顶部模式切换、爆款类型与声音策略

这两个区块在 `video-main` 场景中都属于“借壳复用”，不应按原有商品图套图或视频复刻语义理解。

### 2.1 市场与生成参数

```json
{
  "videoMainMarketFields": {
    "platform": "目标平台，下拉选择",
    "targetMarket": ["大陆", "北美", "欧洲", "日本", "韩国", "东南亚", "中东阿拉伯", "俄罗斯"],
    "copyLanguage": ["无需文案", "简体中文", "繁体中文", "英语", "日语", "韩语", "西班牙语", "法语", "德语", "俄语", "葡萄牙语", "阿拉伯语", "泰语", "印尼语", "越南语", "马来语"],
    "videoReplicaRatio": ["横16:9", "竖9:16", "横4:3", "竖3:4", "正1:1"],
    "videoReplicaDuration": ["5s", "10s", "12s"],
    "videoReplicaResolution": ["480p", "720p", "1080p"]
  }
}
```

说明：

+ 比例、时长、分辨率在 `video-main` 中实际由 `set-pack-strategy` 区块下的 `生成参数` 下拉面板承载
+ 默认值为 `竖9:16`、`10s`、`480p`
+ `targetMarket` 与 `电商套图需求文档` 对齐，统一覆盖 `大陆 / 北美 / 欧洲 / 日本 / 韩国 / 东南亚 / 中东阿拉伯 / 俄罗斯`
+ `copyLanguage` 按跨境内容常用语种全覆盖；它约束的是屏幕可见文字语种，而不只是“文案输出语言”
+ 若用户选择 `无需文案`，则最终 prompt 不再主动生成字幕文案、贴片文案、标题条或额外文字卖点
+ 旧文档中写到的 `4s~15s`、`自适应尺寸`、`横21:9`、仅 `480p/720p`，不符合当前真实实现，当前应以代码枚举为准

### 2.1.0 语言字段作用域说明

产品视频中的“语言”需要拆成两层，而不是只理解为文案语种：

1. `copyLanguage`
   - 负责所有屏幕可见文字的语种约束
   - 包括：字幕、贴片、标题条、卖点字卡、参数字卡、结尾 CTA
2. `videoMainVoiceLanguage`
   - 负责旁白、人声口播、AI 配音的人声语种约束
   - 只在 `videoMainVoiceEnabled=true` 时生效

组装原则：

+ `copyLanguage` 命中后，要求所有屏幕可见文字尽量统一使用该语种，不要混出第二语言
+ `videoMainVoiceLanguage` 命中后，要求旁白或口播统一使用该语种，不要中途切语
+ 若 `copyLanguage=无需文案`，则不生成主动字幕、贴片和卖点字卡；但若用户开启旁白，仍可只保留该语种的人声表达
+ 若同时存在 `copyLanguage` 与 `videoMainVoiceLanguage`，默认要求两者语种一致；若用户显式配置为不同语种，则按用户选择执行，并在 prompt 中明确“屏幕文字语种”与“人声语种”分离
+ 若 `videoReplicaHasSound=无声`，则 `videoMainVoiceLanguage / videoMainVoiceTone / videoMainVoiceCopy` 不参与最终组装
+ 若 `videoReplicaHasSound!=无声` 但 `videoMainVoiceEnabled=false`，则允许仅保留 BGM / 节奏音 / 环境声，不强制生成人声口播

平台规则使用原则：

1. `platform.prompt` 负责写明平台视频语境下的正向方向
2. `platform.required` 负责转成“必须满足”
3. `platform.forbidden` 负责转成“禁止事项”
4. 未命中具体平台时，回退到 `全平台通用（16平台）`
5. `recommendedRatio / recommendedDuration / recommendedResolution / recommendedSound / recommendedTypeOptions` 负责给平台侧默认生成参数和类型优先级
6. 若用户已显式选择比例、时长、分辨率、声音策略或视频类型，则优先使用用户选择，不被平台推荐值覆盖
7. 若用户未显式选择，则按平台推荐值作为默认值；若平台推荐值超出当前页面支持范围，则顺延到最近的可用值

### 2.3 声音策略落地说明

当前产品视频页面沿用了 `videoReplicaHasSound` 字段名，但真实能力边界应按下述方式解释：

1. `无声`
   仅输出画面节奏，不生成旁白、人声、环境声和 BGM。
2. `参考原视频声音`
   当前 `video-main` 不上传参考视频，因此该选项在产品视频场景下应降级理解为“保留强节奏型商业视频声音组织方式”，而不是字面上的“参考某条原视频声音”。
3. `智能匹配声音`
   系统根据商品品类、视频节奏和脚本内容，为成片匹配更合适的声音氛围。

实现要求：

+ 文档和后续产品说明中，需要明确 `video-main` 与 `video-replica` 的语义差异
+ 若后续要彻底消除歧义，建议把 `video-main` 的该字段改名为更中性的 `videoMainSoundStrategy`

## 3. 视频脚本能力

### 3.1 当前真实交互

产品视频的核心交互不是参考视频，而是“脚本驱动”。

页面包含一个 `视频脚本` 文本区：

+ 用户可以直接输入完整视频脚本或镜头描述
+ 用户可以点击 `AI生成` 进入脚本抽屉
+ 抽屉中可填写脚本参数并生成脚本草案
+ 生成后点击 `立即使用`，脚本会回填到主输入区

### 3.2 脚本模式

```json

  ]

```

说明：

+ `AI生成脚本` 与 `自定义脚本` 两个模式字段已存在于实现中
+ 当前主输入区始终允许用户直接填写脚本，因此 `自定义脚本` 更接近数据快照语义，而不是单独的一套显式页面流程
+ 用户点击页面右上角 `AI生成` 时，会强制切到 `ai-script` 并打开抽屉
+ 抽屉内虽然展示 `通用模式（全局设定） / 分镜模式（逐帧精控）` 的切换文案，但目前仅为前端交互态，未形成独立字段写入最终选择快照

### 3.4 AI 帮写逻辑

当前有三类 AI 帮写：

1. 脚本参数 AI 帮写
   - 基于上传文件名与关键词做简单匹配回填
   - 默认优先命中各字段的首个选项或关键词匹配选项
   - 不是真正的多模态理解，仅作为快速填表入口
2. 脚本草案生成
   - 将已选择字段按“标签：值”的方式拼成结构化草案
   - 结尾固定补一段“开场展示商品主体，中段突出卖点，结尾输出行动引导”的模板文案
3. 旁白文案 AI 帮写
   - 基于当前已生成脚本或当前脚本输入，生成一段不超过 200 字的旁白文案
   - 本质是模板化压缩拼接，不是独立的配音策划模型

实现要求：

+ 需求文档必须明确当前 `AI帮写` 为轻量填充，不等同于成熟脚本策划模型
+ 若后续升级为真实多模态脚本生成，需要补充“商品理解 -> 分镜规划 -> 旁白生成”的完整链路

### 3.4.0 AI 帮写提示词落地方案

产品视频中的 `AI帮写` 不应只停留在“按关键词回填首个选项”的弱逻辑，需求文档中应直接给出两套可落地提示词：

1. `帮写选项提示词`
   - 用于给 `卖点名称 / 视频类型 / 营销诉求 / 内容节奏 / 音乐氛围 / 视觉风格 / 目标受众 / 人物出镜方式` 自动推荐选项
2. `最终脚本提示词`

### 3.4.1 从业务合理性看，更推荐“先脚本规划，再生视频”

产品视频不是“把商品信息、卖点、参数、视频类型一次性塞进生成模型”就能稳定做好的能力。更合理的真实业务链路应拆成两阶段：

1. 规划阶段
   - 输入商品信息、卖点信息、平台、市场、语言、时长、比例、视频类型、声音策略
   - 输出脚本规划结果
2. 生成阶段
   - 输入脚本规划结果、商品多视角图、平台规则、品类约束、一致性约束
   - 输出最终视频

原因：

+ 商品信息回答“卖什么”
+ 视频类型、平台、市场、语言回答“适合怎么讲”
+ 脚本规划层负责把“卖点”真正转成“镜头顺序、信息顺序、旁白顺序、字幕顺序”
+ 最终视频生成应消费“规划后的脚本结果”，而不是直接消费“原始卖点列表”

若跳过脚本规划层，常见问题是：

+ 模型知道有哪些卖点，但不知道先讲哪个、后讲哪个
+ 镜头会堆叠信息，但不形成完整叙事
+ 开场、中段、结尾缺少职责分工
+ 字幕、旁白、镜头之间容易脱节

### 3.4.2 商品卖点如何进入最终生成

商品卖点不建议直接平铺到最终视频生成 prompt，而应先经过“卖点结构化 -> 脚本规划 -> 成片生成”三步。

推荐链路：

1. 商品理解
   - 识别商品主体、结构、材质、规格、可展示动作、限制项
2. 卖点结构化
   - 把用户输入卖点拆为主卖点、辅卖点、证据点、禁夸大点
3. 脚本规划
   - 决定每个卖点进入哪个镜头、用字幕讲还是旁白讲、用演示讲还是情绪讲
4. 成片生成
   - 按脚本规划结果生成视频，而不是重新自由发挥卖点顺序

## 4. 旁白能力

### 4.1 开关与字段

```json
{
  "videoMainVoiceFields": {
    "videoMainVoiceEnabled": ["true", "false"],
    "videoMainVoiceLanguage": ["中文普通话", "中文粤语", "英语", "日语", "韩语", "法语", "德语", "西班牙语", "葡萄牙语", "意大利语", "泰语", "越南语"],
    "videoMainVoiceTone": ["清爽女声", "温柔女声", "甜美女声", "知性女声", "浑厚男音", "磁性男声", "年轻男声", "专业广告旁白", "自然种草口吻", "自定义上传"],
    "videoMainVoiceCopy": "0~200字字符串"
  }
}
```

说明：

+ 只有在 `videoMainVoiceEnabled=true` 时，才写入语言、音色和旁白文案字段
+ `videoMainVoiceCopy` 最长 200 字
+ 若用户未填写旁白文案，可通过 `AI帮写` 自动生成一段基础旁白
+ `videoMainVoiceLanguage` 负责“人声说什么语言”，与 `copyLanguage` 的“屏幕文字展示什么语言”不是同一个字段
+ 当视频同时存在字幕、贴片、卖点字卡和旁白时，需要分别约束“屏幕文字语种”和“人声语种”

### 4.2 旁白拼装原则

1. 旁白必须服务商品卖点推进，不能偏离视频脚本主线
2. 旁白风格要与受众、视频类型和营销诉求一致
3. 若用户未开启旁白，则最终 prompt 不应注入配音文案约束
4. 若用户开启旁白但未填写文案，可允许系统按脚本自动补足基础旁白方向
5. 若 `copyLanguage` 与 `videoMainVoiceLanguage` 同时存在且未显式冲突，默认要求屏幕文字语种与旁白语种保持一致
6. 若用户显式指定双语或分语种方案，最终 prompt 需明确区分“屏幕文字语种”和“旁白语种”，避免模型自行混语

## 4.3 选择模特能力

产品视频建议在页面最下方新增一个与“旁白设置”同级的 `选择模特` 模块，采用“开启 / 关闭”开关方式接入。

设计原则：

+ 默认关闭，不影响当前普通商品视频生成链路
+ 开启后，视频生成从“纯商品镜头”升级为“商品 + 指定模特出镜”的视频链路
+ 该模块不替代 `videoMainCharacterParticipation`，而是与“人物出镜方式”配合使用：前者决定“谁出镜”，后者决定“怎么出镜”

### 4.3.1 开关与字段

```json
{
  "videoMainModelFields": {
    "videoMainModelEnabled": ["true", "false"],
    "videoMainModelSourceTab": ["AI生成", "我的模特", "模特偏好"],
    "videoMainModelSourceType": ["AI生成模特", "我的模特", "模特偏好模板"],
    "videoMainSelectedModelId": "string",
    "videoMainSelectedModelImage": "image",
    "videoMainModelPreferenceTags": ["年龄感", "性别气质", "人种肤色", "身材体型", "风格偏好"],
    "videoMainModelBodyPose": "模特姿态识别结果",
    "videoMainModelFramingRange": "模特构图范围识别结果",
    "videoMainModelOcclusionRisks": ["string"]
  }
}
```

说明：

+ `videoMainModelEnabled=false` 时，整组字段不参与最终组装
+ `videoMainModelEnabled=true` 时，用户必须至少确认 1 个已选模特
+ `videoMainModelSourceTab` 对应前台交互入口：`AI生成 / 我的模特 / 模特偏好`
+ `videoMainSelectedModelId` 和 `videoMainSelectedModelImage` 是最终真正参与生成的人物参考
+ `videoMainModelBodyPose / videoMainModelFramingRange / videoMainModelOcclusionRisks` 可复用模特试穿中的模特识别链路，作为视频人物约束输入

### 4.3.2 与模特试穿能力的关系

产品视频中的 `选择模特` 不是独立的“试穿图生成”，但可以复用模特试穿中的模特来源和人物约束能力：

1. 复用 `AI生成 / 我的模特 / 模特偏好` 三种来源模式
2. 复用“已选模特 + AI 生成记录”的交互结构
3. 复用模特识别字段：
   - `modelSourceType`
   - `modelBodyPose`
   - `modelOcclusionRisks`
   - `framingRange`
4. 复用模特约束原则：
   - 必须保持同一人物身份、脸部、发型、体态和气质稳定
   - 不得在不同镜头中替换人物

### 4.3.3 选择模特拼装原则

1. 若 `videoMainModelEnabled=false`，则最终 prompt 不应写入任何指定模特约束，系统按普通产品视频处理
2. 若 `videoMainModelEnabled=true`，则最终 prompt 必须显式加入“人物参考约束”
3. 开启模特后，`videoMainCharacterParticipation` 只负责“人物如何出镜”，不得覆盖真实已选模特身份
4. 若脚本规划要求“无人物纯产品展示”，但用户开启了指定模特，应优先按用户开启结果执行，并在脚本规划中至少安排部分人物出镜镜头
5. 若商品品类不适合人物出镜，或人物出镜会损害商品识别，则脚本规划应控制模特出镜占比，优先保证商品主体展示

### 4.3.4 模特约束建议文案


### 4.3.5 人物出镜方式与选择模特的分工

产品视频中不建议继续使用“人物适配”这种会同时混合“人物身份”和“出镜方式”的概念，而应拆成两层：

1. `videoMainCharacterParticipation`
   - 解决“人物怎么出镜”
   - 例如：`无人物 / 局部出镜 / 半身出镜 / 全身出镜 / 讲解型出镜 / 体验型出镜`
2. `选择模特`
   - 解决“谁来出镜”
   - 由已选模特或模特偏好产出标准化模特信息

平衡原则：

1. 未开启选择模特时，`videoMainCharacterParticipation` 可单独生效
2. 开启选择模特后，人物身份以模特标准化信息为准
3. 开启选择模特后，`videoMainCharacterParticipation` 只作为出镜方式约束，不再决定人物身份
4. 若 `videoMainCharacterParticipation=无人物` 但用户已开启选择模特，则以用户开启结果为准，并自动回退到最轻人物参与方式，例如 `局部出镜` 或 `体验型出镜`

### 4.3.6 模特标准化信息生成链路

最终视频生成不建议直接把 `videoMainSelectedModelId / videoMainModelPreferenceTags / videoMainModelBodyPose` 等前台字段原样拼入 prompt，而应先经过“模特识别/偏好解析提示词”，产出一份可供视频模型直接理解的标准化模特信息。

推荐链路：

1. 用户选择模特来源
   - `AI生成`
   - `我的模特`
   - `模特偏好`
2. 系统根据来源类型调用对应提示词
   - 若有明确已选模特图：走“模特识别提示词”
   - 若只有偏好标签：走“模特偏好解析提示词”
3. 统一输出标准化模特信息
4. 最终视频生成 prompt 只消费“标准化模特信息”，不直接消费零散前台字段

## 5. 最终提示词组装原则

产品视频最终 prompt 至少应包含以下信息层：

1. 任务目标：基于商品多视角图生成产品视频
2. 平台规则：平台视频语境、required、forbidden
3. 品类约束：不同品类对应不同的结构保真重点、动作重点和卖点重点
4. 商品一致性约束：颜色、材质、结构、细节、比例稳定
5. 市场字段值扩展：目标市场、文案语种
6. 创作参数：模式、时长、比例、分辨率、声音策略
7. 卖点结构化结果：主卖点、辅卖点、证据点、禁夸大点
8. 脚本规划结果：镜头顺序、每镜头卖点、字幕策略、旁白策略、收束方式
9. 脚本字段值扩展：视频类型、营销诉求、节奏、音乐氛围、视觉风格、受众、人物出镜方式
10. 旁白层信息：是否开启旁白、语言、音色、旁白文案
11. 模特层信息：是否开启选择模特、模特来源、已选模特、模特姿态与构图约束
12. 通用质量约束：商业可用、稳定、无明显闪烁漂移

补充说明：

+ 从业务合理性上，`脚本规划结果` 应高于“原始卖点文本”
+ 最终视频生成应优先消费 `scenePlan / scriptPlan`，而不是直接对原始卖点自由发挥
+ 若没有显式脚本规划结果，才回退为“字段值 + 原始脚本文本”的弱规划模式

## 5.1 品类约束

从成片效果看，产品视频需要独立的品类约束。原因不是为了“分类更完整”，而是为了减少不同品类在视频中最常见的出错方式。

如果只使用通用商品一致性约束，系统通常只能做到“这还是这个商品”，但很难稳定做到：

+ 服饰的版型和走动形变自然
+ 鞋靴的上脚受力和鞋型比例准确
+ 箱包的包型、开合和五金细节稳定
+ 美妆个护的质地、肤感和使用逻辑可信
+ 食品饮料的卖相、流动状态和食欲感自然
+ 家电数码的接口、按键、灯效和操作反馈准确

所以产品视频建议采用“两层约束”：

1. 通用品类基线
   适用于所有商品，保证主体真实、卖点清楚、镜头围绕商品展开。
2. 高频品类专项约束
   针对高频类目补充更细的结构、材质、动作和展示规则。

### 5.3 最终生成组装顺序

建议后端按以下顺序组装最终 prompt：

1. 基础任务头
2. 平台规则段
3. 品类规则段
4. 商品一致性段
5. 参数行
6. 参数与市场字段值扩展段
7. 卖点结构化段
8. 镜头执行脚本段
9. 成片风格与出镜要求段
10. 人声与配音要求段
11. 人物与模特出镜要求段
12. 通用质量约束段
13. 通用负向约束段

这一层需要明确区分：

1. 前置规划字段
   - 用于 AI 帮写选项、卖点结构化、脚本规划、最终脚本生成
   - 包括：`videoMainType / videoMainMarketingNeed / videoMainRhythm / videoMainMusicMood / videoMainVisualStyle / videoMainAudience / videoMainCharacterParticipation`
2. 成片风格与出镜要求
   - 用于最终视频生成 prompt 中补充镜头脚本难以完整承接的全局约束
   - 建议只保留：`videoMainVisualStyle / videoMainMusicMood / videoMainAudience / videoMainCharacterParticipation`

原则：

+ `videoMainType / videoMainMarketingNeed / videoMainRhythm` 原则上应被脚本规划过程与镜头脚本内容吸收，不建议在最终生成视频 prompt 中再次逐条重复
+ `videoMainVisualStyle / videoMainMusicMood / videoMainAudience / videoMainCharacterParticipation` 仍可保留，因为这些更偏全局风格、表达气质和人物出镜方式，脚本文本不一定能完整约束
+ 最终生成视频的 prompt 应以“镜头脚本内容”为主体，而不是再次塞入整套前置参数；脚本规划结果更适合作为前一阶段的中间产物
+ `videoMainScriptPlan` 属于前置规划产物，用于生成镜头脚本，不再作为最终生成视频 prompt 的独立段落参与拼装

字段命中顺序建议：

1. `platform` -> 命中 `platformRulesByTool`，同时可带出平台推荐参数 recommendedRatio / recommendedDuration / recommendedResolution / recommendedSound / recommendedTypeOptions
2. `productCategory` -> 命中 `productVideoCategoryRules`
3. `targetMarket / copyLanguage / videoReplicaRatio / videoReplicaDuration / videoReplicaResolution / videoReplicaHasSound` -> 命中 `videoMainOptionValueExpansions`
4. `videoMainVoiceLanguage` -> 命中 `videoMainOptionValueExpansions.videoMainVoiceLanguage`

9. `supplement` 或生成脚本 -> 进入“镜头执行脚本段”

## 6. 与相邻功能的边界

### 6.1 与 `video-replica` 的边界

- `video-main`：无参考视频，核心是“脚本驱动的产品视频生成”
- `video-replica`：有参考视频，核心是“参考视频爆款逻辑迁移”

### 6.2 与 `video-replace` 的边界

- `video-main`：从商品图直接生成全新视频
- `video-replace`：基于原视频保留动作与运镜，只替换视频中的商品主体

### 6.3 当前复用带来的命名问题

当前 `video-main` 复用了 `video-replica-setup` 与 `videoReplica*` 字段名，因此会出现以下语义不完全贴合的问题：

1. `videoReplicaHasSound` 在产品视频中不是真正的“参考原视频声音”
2. `videoReplicaMode` 在产品视频中实际表示“产品视频生成模式”
3. `video-replica-setup` 区块名本身带有复刻语义，但当前被复用为通用视频参数区

建议：

+ UI 层可先继续复用组件
+ 配置层和文档层应逐步收敛为 `videoMain*` 命名，避免后续接入真实产品视频模型时语义混乱

## 8. 当前版本结论

当前 `video-main` 已落地的真实能力可以定义为：

+ 输入为同一商品的 1~5 张多视角图片
+ 用户可配置卖点信息、市场信息与视频基础参数
+ 用户可在普通模式下选择多个爆款类型，并为每个类型指定数量
+ 用户可直接写脚本，也可通过参数生成基础脚本草案
+ 用户可开启旁白并补充语言、音色和旁白文案
+ 用户可在页面底部开启“选择模特”，从 `AI生成 / 我的模特 / 模特偏好` 中指定人物参考
+ 系统最终产出 1 条产品视频

当前 `video-main` 尚未落地的能力也应明确标注：

+ 未上传参考视频，因此不具备真正的“视频复刻”能力
+ 脚本 AI 帮写仍偏轻量，未形成完整的商品理解式脚本策划链路
+ 抽屉中的“逐帧精控”当前仅为交互文案，未形成独立结构化分镜字段
